VLSI Design Flow: RTL to GDS

Notes curated for EcrioniX · Sep 24, 2026 · ~12 min read
🎥 Source Lecture: "VLSI Design Flow: RTL to GDS - Course Intro" (NPTEL-NOC IITM / IIIT Delhi, Prof. Snehasish Ghorai)

Core Concept in 60 Seconds

Modern semiconductor chips pack billions of nanometer-scale transistors onto a small piece of silicon. Because direct transistor-level manual design is impossible at this scale, the workflow is split into a hierarchical, multi-stage abstraction flow: translating high-level Register-Transfer Level (RTL) into physical GDS II layout using specialized EDA tools. EDA tools are non-push-button and heavily iterative, requiring silicon architects to constantly balance conflicting physical trade-offs (PPA: Power, Performance, Area).

1. The Nanometer Silicon Challenge

Modern microprocessors, GPUs, and AI accelerators integrate tens of billions of transistors into silicon chips measuring just a few square centimeters. Individual transistor gate lengths are now smaller than biological viruses (measuring mere nanometers across).

Designing an integrated circuit at this scale with individual transistor schematics is completely intractable for humans. VLSI design overcomes this complexity by adopting a structured abstraction hierarchy: transforming high-level behavioral algorithms step-by-step into physical lithography masks.

2. RTL-to-GDS Flow Hierarchy

The transformation from an initial product idea to physical silicon follows a structured pipeline across distinct engineering milestones:

Stage Input Artifact Primary Objectives & Tasks Output Artifact
System-Level Design Architectural Spec Defines target functionality (compute, cache, bus architecture, IOs) and models high-level behavior. RTL Description (Verilog / SystemVerilog)
Logic Synthesis RTL + Target PDK Library (.lib) + Constraints (.sdc) Translates Verilog into generic gates, optimizes boolean logic, and maps to standard cells in the foundry library. Gate-Level Netlist (.v)
Physical Design Gate Netlist + LEF + Floorplan Def Floorplanning, power grid distribution, cell placement, Clock Tree Synthesis (CTS), and signal routing. DEF / Routing DB
Physical Verification & Tapeout Physical Layout DB DRC (Design Rule Checking), LVS (Layout vs Schematic), ERC (Electrical Rules), and final timing sign-off (STA). GDS II / OASIS Layout
Silicon Fabrication GDS II Tapeout Mask Data Foundry photolithography, etching, doping, metallization on silicon wafers, packaging, and wafer testing. Packaged Silicon IC

4. The "Non-Push-Button" Nature & The Feedback Loop

A fundamental misconception among software engineers entering hardware design is treating Electronic Design Automation (EDA) tools like software compilers (e.g., gcc main.c -o main). In hardware, EDA tools are never push-button.

The Engineer in the Loop

Commercial EDA tools (Synopsys Design Compiler, Cadence Innovus, Siemens Questa, or Open-Source OpenROAD) rely on human guidance. If the initial input constraints are slightly flawed or overly pessimistic, the tools will spend hours optimizing impossible paths, ballooning area and burning power.

The flow is inherently an iteration loop:

  1. The designer supplies initial RTL, library definitions (PDK), and SDC timing constraints.
  2. The tool runs logic synthesis and physical layout steps.
  3. The engineer thoroughly analyzes diagnostic reports (timing slack, congestion heatmaps, IR drop, DRC errors).
  4. When timing or physical criteria fail, the engineer returns to earlier stages, adjusting floorplan shapes, restructuring Verilog logic, or tightening constraints.

5. PPA Multivariable Optimization

Silicon engineering is an uncompromising balancing act. The three pillars of PPA continuously push against one another:

  • Performance vs. Power: Increasing clock speed demands higher supply voltage ($V_{dd}$) and larger drive-strength cells. Dynamic power scales quadratically ($P \propto C \cdot V^2 \cdot f$), meaning doubling speed can cause thermal throttling.
  • Performance vs. Area: To meet aggressive setup timing on critical paths, tools upsize standard cells and insert parallel pipelines, swelling silicon real estate.
  • Area vs. Yield: Larger silicon die sizes drastically decrease wafer yield—due to random dust particle defects—increasing the per-chip manufacturing cost.

6. Synthesizable RTL Datapath Example

The implementation flow starts with clean, synthesizable hardware descriptions. Below is a parameterized registered accumulator that serves as a standard datapath unit entering the RTL-to-GDS flow:

accumulator_datapath.v Clean Synthesizable RTL 
// Parameterized Registered Accumulator Module
module accumulator_datapath #(
    parameter WIDTH = 16
)(
    input  wire             clk,
    input  wire             rst_n,      // Asynchronous Active-Low Reset
    input  wire             enable,
    input  wire [WIDTH-1:0] data_in,
    output reg  [WIDTH-1:0] accum_out
);

    // Sequential Register Logic: Infers D-Flip-Flops
    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            accum_out <= {WIDTH{1'b0}};
        end else if (enable) begin
            accum_out <= accum_out + data_in;
        end
    end

endmodule

7. Common RTL & EDA Tool Traps

Trap 1: Unintended Latch Inference

If a combinational always @(*) block does not assign an output under all possible input conditions (e.g., missing else branch or incomplete case statement), the synthesis tool assumes the output must hold its previous value. It infers a transparent latch instead of pure combinational gates. Latches complicate Static Timing Analysis (STA) and clock tree synthesis immensely.

Trap 2: Over-Constraining Timing

Junior designers often apply arbitrary 50% timing margins in their .sdc files hoping for extra safety. This forces the physical synthesis engine to aggressively upsize cells and insert thousands of unnecessary delay buffers, causing routing congestion and severe dynamic power waste.

8. High-Yield Interview & Exam Questions

Q1: Why are EDA tools in the RTL-to-GDS flow characterized as "non-push-button"?

Model Answer: EDA tools are heuristic solvers tackling NP-hard optimization problems (e.g., cell placement and routing). They cannot automatically infer design intent or optimal physical compromises. Designers must formulate accurate physical/timing constraints (SDC), inspect diagnostic reports (STA slack, congestion, DRC), and execute iterative feedback adjustments to close timing and pass physical verification.

Q2: What is a GDS II file, and what specific information does it supply to a semiconductor foundry?

Model Answer: GDS II (Graphic Database System II) is the industry-standard binary format representing the final geometric layout of an integrated circuit. It contains the exact planar polygonal coordinates, layer assignments, metal interconnects, and via geometries needed by the foundry to create optical photomasks for physical silicon photolithography.

Q3: Explain how PPA trade-offs manifest during clock tree synthesis (CTS).

Model Answer: During CTS, the tool inserts clock buffers to balance clock arrival times across all sequential elements and minimize skew (optimizing Performance). However, every clock buffer consumes silicon Area and toggles at 100% activity factor on every cycle, contributing up to 30–40% of total dynamic Power. The engineer must balance skew tolerance against the clock tree's power footprint.

Quick Revision Checklist

  • Scale: Billions of nanoscale transistors packed on chips require hierarchical abstraction layers to design.
  • Flow: The pipeline progresses through System Spec → RTL → Synthesis → Physical Design → GDS II → Fabrication.
  • GDS II: The final layout file format containing geometrical mask polygons sent to the foundry.
  • Non-Push-Button: Physical design requires continuous human diagnostic analysis and feedback loop refinement.
  • PPA Balancing: Every change to clock frequency, power budget, or die area impacts the other two variables.
