APB Wait-State Handling — PREADY Behavior

On-Chip Protocols · memory, fifo, protocols, apb, uart, hard, amba-apb

Extend an APB slave to insert exactly 1 wait state (PREADY=0 for one cycle during ACCESS phase) before completing any transfer.

Verified Synthesizable RTL 
module top_module(
  input   pclk,
  input   preset_n,
  input   psel,
  input   penable,
  input   pwrite,
  output  pready
);
  reg wait_done;

  always @(posedge pclk or negedge preset_n) begin
    if (!preset_n)
      wait_done <= 1'b0;
    else if (psel && penable)
      wait_done <= ~wait_done;
    else
      wait_done <= 1'b0;
  end

  assign pready = wait_done;
endmodule

Architectural Deep Dive & Implementation Walkthrough
In the AMBA 3 APB specification, slaves can extend the ACCESS phase by driving `pready = 0`. The APB bridge master is obligated to hold all control signals (`psel, penable, paddr, pwrite, pwdata`) completely static until the cycle where the slave returns `pready = 1`.

Silicon & Hardware Engineering Notes
🛠️ ASIC vs FPGA Hardware Considerations
Wait states allow slow peripherals (e.g. analog ADCs, flash memory, EEPROMs) to interface with high-speed processors without needing asynchronous FIFOs.
