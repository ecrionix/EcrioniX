Radix-4 Booth Encoder

Combinational Design · combinational, arithmetic, multiplier

The lookup table at the heart of every fast hardware multiplier: examine 3 overlapping bits of the multiplier and decide whether to add 0, ±1x, or ±2x of the multiplicand this cycle — halving the number of partial products versus naive shift-and-add.

Module Specification
Write a synthesizable Verilog module named top_module matching the ports below exactly.
Concept: Radix-4 Booth encoding slides a 3-bit window (one bit higher, current, one bit lower) across the multiplier and classifies each window into one of 5 actions: add 0, add/sub 1x, or add/sub 2x the multiplicand — so a multiplier only needs half as many partial-product rows as a plain shift-and-add design. The full 8-entry table is: 000→0, 001/010→+1x, 011→+2x, 100→−2x, 101/110→−1x, 111→0. The easy way to get this wrong is swapping which pattern gets the ×1 weight and which gets the ×2 weight — e.g. encoding 011 (which should be +2x, since it's the boundary where two isolated 1-bits look like a single run ending) as +1x instead. It still produces a plausible-looking partial product, just the wrong magnitude.

Hardware Implementation & Synthesizable RTL Rules

      
A production-ready RTL implementation requires synthesizable design intent:

      
    
        
  • No Simulation Delays: Never include #delay statements inside synthesizable RTL modules.
    • 
        
  • Combinational vs Sequential Assignments: Use blocking assignments (=) only inside combinational always @(*) blocks; use non-blocking assignments (<=) exclusively inside edge-triggered always @(posedge clk) blocks.
    • 
        
  • Latch Avoidance: Ensure all outputs are assigned under every conditional branch (if/else and case) to prevent unintended latch inference.
