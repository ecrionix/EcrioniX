Hint 1: Conceptual Direction & Hardware Primitives
Never pass multi-bit data directly through flip-flop synchronizers; physical wire delays cause bits to arrive in different destination clock cycles.
Hint 2: Implementation Architecture & Approach
Hold src_data static in a register while a single 1-bit src_req signal crosses into the destination domain via a 2-flop synchronizer.
Hint 3: Edge Cases, Timing & Verilog Syntax
Once destination samples the synchronized request, it captures the stable data and returns an acknowledge (dst_ack) through another 2-flop synchronizer back to the source.

module top_module (
  input  wire        src_clk,
  input  wire        src_rst_n,
  input  wire        src_valid,
  input  wire [15:0] src_data,
  output reg         src_ready,
  input  wire        dst_clk,
  input  wire        dst_rst_n,
  output reg         dst_valid,
  output reg  [15:0] dst_data
);

  // Source domain state
  reg [15:0] data_hold;
  reg        src_req;

  // Synchronize src_req to dst_clk
  reg req_s1, req_s2;

  // Destination domain state
  reg dst_ack;
  reg req_s2_d;

  // Synchronize dst_ack to src_clk
  reg ack_s1, ack_s2;

  // Source domain logic
  always @(posedge src_clk or negedge src_rst_n) begin
    if (!src_rst_n) begin
      src_ready <= 1'b1;
      src_req   <= 1'b0;
      data_hold <= 16'h0;
      ack_s1    <= 1'b0;
      ack_s2    <= 1'b0;
    end else begin
      ack_s1 <= dst_ack;
      ack_s2 <= ack_s1;

      if (src_ready && src_valid) begin
        src_ready <= 1'b0;
        src_req   <= 1'b1;
        data_hold <= src_data;
      end else if (src_req && ack_s2) begin
        src_req <= 1'b0;
      end else if (!src_req && !ack_s2 && !src_ready) begin
        src_ready <= 1'b1; // Completed 4-phase handshake
      end
    end
  end

  // Destination domain logic
  always @(posedge dst_clk or negedge dst_rst_n) begin
    if (!dst_rst_n) begin
      req_s1    <= 1'b0;
      req_s2    <= 1'b0;
      req_s2_d  <= 1'b0;
      dst_ack   <= 1'b0;
      dst_valid <= 1'b0;
      dst_data  <= 16'h0;
    end else begin
      req_s1    <= src_req;
      req_s2    <= req_s1;
      req_s2_d  <= req_s2;
      dst_valid <= 1'b0;

      if (req_s2 && !req_s2_d) begin
        // Rising edge of request in destination domain
        dst_data  <= data_hold;
        dst_valid <= 1'b1;
        dst_ack   <= 1'b1;
      end else if (!req_s2 && dst_ack) begin
        dst_ack <= 1'b0;
      end
    end
  end

endmodule

Architectural Deep Dive & Implementation Walkthrough
Why Multi-Bit Buses Cannot Use Simple Synchronizers


If you connect a 16-bit data bus directly to 16 parallel 2-flop synchronizers across unrelated clock domains, differences in silicon routing delays (skew) and metastability resolution will cause some bits to arrive in clock cycle $N$ and others in cycle $N+1$. The destination would sample corrupted intermediate values.


The 4-Phase Handshake Protocol


    
  
  1. Phase 1: Source latches src_data into a holding register and asserts src_req = 1.
    2. 
  
  2. Phase 2: src_req crosses into dst_clk through a standard 2-flop synchronizer. Since data has been stable for multiple cycles, destination safely latches dst_data and asserts dst_ack = 1.
    3. 
  
  3. Phase 3: dst_ack synchronizes back into src_clk. Source deasserts src_req = 0.
    4. 
  
  4. Phase 4: Destination deasserts dst_ack = 0. Once source sees ack drop, it asserts src_ready = 1, ready for the next transfer.
    5. 



      
Common RTL Designer Pitfalls
⚠️ Common Mistakes to Avoid
Allowing src_data to change before the full 4-phase handshake completes.


      
Silicon & Hardware Engineering Notes
🛠️ ASIC vs FPGA Hardware Considerations
Although latency is 6-8 clock cycles, multi-bit handshakes consume minimal logic compared to an asynchronous FIFO when transmitting low-bandwidth configuration words.
