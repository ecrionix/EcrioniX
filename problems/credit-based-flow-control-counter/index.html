Credit-Based Flow Control Counter

Sequential Design · sequential, counter, protocol

Track available send credits so a sender never transmits more than the receiver has buffer space for — the flow-control mechanism behind NoC and high-speed serial links.

Module Specification
Write a synthesizable Verilog module named top_module matching the ports below exactly.
Concept: A sender may only spend a credit when it actually has one: if(send && can_send) credits<=credits-1, alongside independently gaining one back on credit_return. Dropping the can_send guard on the decrement lets send fire with zero credits available, underflowing the counter to its maximum value — which is doubly dangerous here, because can_send is derived from credits!=0, so the underflow doesn't just corrupt the count, it flips the flow-control gate back to "go ahead and send more" at exactly the moment the sender should be blocked.

Concept: A sender may only spend a credit when it actually has one: if(send && can_send) credits<=credits-1, alongside independently gaining one back on credit_return. Dropping the can_send guard on the decrement lets send fire with zero credits available, underflowing the counter to its maximum value — which is doubly dangerous here, because can_send is derived from credits!=0, so the underflow doesn't just corrupt the count, it flips the flow-control gate back to "go ahead and send more" at exactly the moment the sender should be blocked.

Hardware Implementation & Synthesizable RTL Rules

      
A production-ready RTL implementation requires synthesizable design intent:

      
    
        
  • No Simulation Delays: Never include #delay statements inside synthesizable RTL modules.
    • 
        
  • Combinational vs Sequential Assignments: Use blocking assignments (=) only inside combinational always @(*) blocks; use non-blocking assignments (<=) exclusively inside edge-triggered always @(posedge clk) blocks.
    • 
        
  • Latch Avoidance: Ensure all outputs are assigned under every conditional branch (if/else and case) to prevent unintended latch inference.
