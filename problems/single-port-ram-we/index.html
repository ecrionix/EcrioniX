module top_module(
  input        clk,
  input        we,
  input  [4:0] addr,
  input  [7:0] din,
  output reg [7:0] dout
);
  reg [7:0] ram [0:31];

  always @(posedge clk) begin
    dout <= ram[addr]; // read-first: sample prior memory content
    if (we)
      ram[addr] <= din;
  end
endmodule

Timing Constraints & Synthesizable RTL Rules

      

        
⚡ Synthesizable Implementation Guidelines

        

          
Timing Contract: When we=1 at posedge clk, old memory contents are presented on dout (read-first), while din is written into memory.

          
Synthesis Constraints: Single-port architecture: read and write share the same clock and address bus.

        

      


      
Architectural Deep Dive & Implementation Walkthrough
When writing to the same address being read, memory architectures support three behaviors: 1) Read-first: output reflects old memory contents before write. 2) Write-first: output reflects newly written data. 3) No-change: output remains latched to prior cycle data. Read-first is the default native behavior of most FPGA BRAM primitives.


      
Common RTL Designer Pitfalls
⚠️ Common Mistakes to Avoid
['Assigning `dout <= din` during writes, turning it into write-first mode instead of read-first mode.', 'Using blocking assignments, which breaks delta-cycle read-first ordering in simulation.']


      
Silicon & Hardware Engineering Notes
🛠️ ASIC vs FPGA Hardware Considerations
Selecting read-first mode in BRAM saves power and avoids bypass multiplexer logic in FPGA routing fabrics.
