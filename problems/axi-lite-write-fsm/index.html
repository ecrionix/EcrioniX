Problem Statement & Requirements

      
Accept an address+data write beat, then hold the response channel until the master acknowledges — the handshake FSM behind every AXI4-Lite peripheral.

      
Hardware design teams at leading semiconductor firms evaluate these exact port contracts, race-condition assertions, and corner cases during technical design reviews and ASIC engineer interviews.

      
      
Concept: Once awready/wready pulse to accept an address+data beat, the FSM must drop them back to 0 before moving into the response phase — leaving them asserted through RESP would tell the master it can send a second write before the first one's response (bvalid/bready) has even completed, which is a real AXI protocol violation that breaks ordering guarantees the whole bus depends on. Forgetting exactly that one deassertion (awready<=0; wready<=0;) when entering RESP is an easy line to drop and a serious one to miss.

  input  awvalid,
  output reg awready,

  output reg bvalid,

  // Your code here — IDLE: accept awvalid&&wvalid for 1 cycle (awready=wready=1), move to RESP.
  // RESP: deassert awready/wready, assert bvalid until bready, then back to IDLE.

Frequently Asked Questions

      
What does AXI4-Lite Write Channel FSM require?
Accept an address+data write beat, then hold the response channel until the master acknowledges — the handshake FSM behind every AXI4-Lite peripheral. Implement it as Verilog module top_module matching the listed ports.

      
Is this design combinational or sequential?
Tags: sequential, protocol, amba, fsm. If a clock signal is present in the port table, implement it as sequential logic; otherwise, use continuous assignments or combinational blocks.

      
How is my solution graded?
A hidden SystemVerilog testbench simulates your module in the cloud judge. You pass when all directed corner cases match the golden model and the VCD timing waveform matches the contract.

      
How does this challenge help with semiconductor interviews?
