module top_module (
  input  wire        ACLK,
  input  wire        ARESETn,
  input  wire        s_valid,
  output wire        s_ready,
  input  wire [31:0] s_data,
  output reg         m_valid,
  input  wire        m_ready,
  output reg  [31:0] m_data,
  output wire        stall_detected
);

  assign stall_detected = m_valid && !m_ready;
  assign s_ready = !m_valid || m_ready;

  always @(posedge ACLK or negedge ARESETn) begin
    if (!ARESETn) begin
      m_valid <= 1'b0;
      m_data  <= 32'h0;
    end else begin
      if (s_ready) begin
        m_valid <= s_valid;
        if (s_valid) begin
          m_data <= s_data;
        end
      end
    end
  end

endmodule

Architectural Deep Dive & Implementation Walkthrough
The AMBA AXI Valid-Ready Handshake Contract


In all 5 AXI channels (AR, R, AW, W, B) as well as AXI4-Stream, data movement is governed by the two-way VALID / READY handshake contract:


    
  
  • The Transfer Point: Data is consumed strictly when VALID = 1 and READY = 1 at a positive clock edge.
    • 
  
  • The Stability Requirement: Once a master asserts VALID, it must maintain VALID = 1 and keep the payload unchanged until READY = 1 is observed.
    • 
  
  • Deadlock Prevention: The specification forbids VALID from waiting for READY combinationally. A master cannot check if a slave is ready before deciding whether to assert VALID.
    • 



      
Common RTL Designer Pitfalls
⚠️ Common Mistakes to Avoid
Allowing payload signals to mutate while VALID is high and READY is low, or creating a combinational loop from READY to VALID.


      
Silicon & Hardware Engineering Notes
🛠️ ASIC vs FPGA Hardware Considerations
Cascading simple valid-ready stages introduces a half-bandwidth bubble (1 beat every 2 cycles). Eliminating this requires a skid buffer (Problem 45).
