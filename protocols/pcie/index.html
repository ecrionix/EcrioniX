In PCIe Gen 1–5, small payloads suffer severely from header overhead: a 16-byte write with a 4DW header and CRC consumes 38 bytes on the wire, yielding only ~42% bus efficiency. For high-bandwidth DMA, designers configure the Maximum Payload Size (MPS) to 512B or 1024B, raising efficiency above 96%.

1. What is PCIe?

PCIe (PCI Express) is a high-speed point-to-point serial interconnect standard that connects components inside modern computing platforms — GPUs, NVMe SSDs, network interface cards (NICs), sound cards, and hardware accelerators. It was introduced in 2003 by the PCI-SIG (led by Intel) to supersede the older parallel PCI and AGP buses.

Unlike the legacy PCI architecture which was a shared parallel bus (where all devices competed for the same clock and 32/64 data lines, causing bus arbitration latency and trace-length skew bottlenecks), PCIe is strictly point-to-point. Every device communicates via dedicated full-duplex serial lanes, guaranteeing full non-blocking bandwidth.

Key Architectural Shift from PCI to PCIe:

• PCI: Shared parallel bus → devices take turns arbitrating for the bus. Trace-to-trace clock skew limited bus speed to 33 MHz or 66 MHz.

• PCIe: Point-to-point dual-simplex serial links with embedded clocking (8b/10b or 128b/130b) and LVDS signaling, scaling into multi-gigatransfer rates without clock-data skew limits.

2. PCIe System Topology: Root Complex, Switches & Endpoints

PCIe employs a hierarchical tree topology. Every device in the system is reachable from the host CPU through an organized hierarchy of Root Complex (RC) → Switches → Endpoints.

  • Root Complex (RC): Sits at the apex of the PCIe hierarchy, connecting the host processor and memory subsystem to the PCIe I/O fabric. RC originates transactions on behalf of the CPU and processes DMA requests originating from endpoints.
  • PCIe Switches: Act as packet routers. Logically, a switch consists of one upstream virtual PCI-to-PCI bridge and multiple downstream virtual bridges, forwarding TLPs based on address, ID (Bus/Device/Function), or implicit routing.
  • Endpoints (EP): Peripheral devices that terminate PCIe links. They request memory reads/writes via DMA and implement Configuration Space Base Address Registers (BARs) to expose memory or I/O windows.

3. Physical Lanes: x1, x2, x4, x8, x16 Scalability

A PCIe physical link consists of one or more lanes. A single lane (x1) contains four physical wires configured as two low-voltage differential pairs: one transmit pair ($TX^+ / TX^-$) and one receive pair ($RX^+ / RX^-$). This enables concurrent, bidirectional (full-duplex) communication.

Lane Negotiation & Bifurcation:

During link training (LTSSM Configuration state), devices negotiate link width. A x16 device plugged into a x8 or x4 physical slot automatically trains down to x8 or x4 without software intervention. Furthermore, modern motherboards support PCIe Bifurcation, splitting a x16 slot into multiple independent links (e.g., x8/x8 or x4/x4/x4/x4) to host quad M.2 NVMe drives.

Gen 6 Paradigm Shift — PAM4 & FLIT Mode:

In Gen 1–5, PCIe used NRZ (Non-Return-to-Zero) signaling: 1 symbol = 1 bit. Scaling beyond 32 GT/s caused catastrophic high-frequency dielectric loss on PCB traces. Gen 6 switched to PAM4 (Pulse Amplitude Modulation 4-level), transmitting 2 bits per symbol at 32 GHz Nyquist frequency. Because PAM4 has 3 eye openings with smaller eye heights, Bit Error Rate (BER) increases from $10^{-12}$ to $10^{-5}$. To counteract this, Gen 6 introduced Forward Error Correction (FEC) operating over fixed 256-byte FLITs (Flow Control Units).

5. The PCIe 3-Layer Protocol Architecture

PCIe is structured into three discrete protocol layers, each handling specific functional requirements of point-to-point packet delivery.

LAYER 3 TRANSACTION LAYER
Responsible for assembly and disassembly of Transaction Layer Packets (TLPs). Manages split transactions (requests and completions), credit-based flow control (Posted, Non-Posted, Completion credits), Ordering Rules (PCI Ordering / Relaxed Ordering), and End-to-End CRC (ECRC).
LAYER 2 DATA LINK LAYER (DLL)
Guarantees reliable, loss-free point-to-point packet delivery. Appends a 12-bit or 16-bit Sequence Number and 32-bit Link CRC (LCRC) to outgoing TLPs. Maintains the Replay Buffer. Executes the ACK/NAK protocol to immediately retransmit corrupted TLPs. Generates and consumes Data Link Layer Packets (DLLPs) for flow control credits and power management.
LAYER 1 PHYSICAL LAYER (PHY)
Divided into Logical PHY and Electrical PHY.
• Logical PHY: Framing tokens (STP, END), scrambler/descrambler (LFSR to prevent EMI), 8b/10b or 128b/130b encoding/decoding, lane-to-lane deskew FIFO, and the LTSSM state machine.
• Electrical PHY: SerDes transmitters, receiver equalization (CTLE, DFE), PLL clock generation, Clock Data Recovery (CDR), and differential driver pairs ($TX^+/TX^-$, $RX^+/RX^-$).

6. TLP Anatomy: Header, Payload & Routing

A Transaction Layer Packet carries application requests and responses across the PCIe link. Every TLP begins with a 3-DWORD (12-byte) or 4-DWORD (16-byte) header, followed by an optional data payload (up to 4096 bytes) and an optional 32-bit ECRC.

Address Routing vs ID Routing:

• Address Routing: Switches inspect the target memory address and compare it against their internal Base and Limit registers to route the packet downstream toward the appropriate endpoint.

• ID Routing: Used for Configuration and Completion packets. Switches examine the 16-bit Bus[7:0] : Device[4:0] : Function[2:0] tuple to steer packets through the correct downstream port.

7. Credit-Based Flow Control

Unlike network protocols (like Ethernet or TCP) that drop packets when receiver buffers are congested, PCIe uses a strictly lossless credit-based flow control mechanism managed by the Transaction Layer. A transmitter is never allowed to send a TLP unless it has proven sufficient buffer credits from the receiver.

Credit TypeApplies ToUnit of CreditPurpose
Posted (P)Memory Writes (MWr), Messages (Msg)Headers (units) + Data (16B / 4DW)Fire-and-forget; no completion returned
Non-Posted (NP)Memory Reads (MRd), Config, I/OHeaders (units) + Data (16B)Split transactions requiring completions
Completion (Cpl)Cpl, CplD responsesHeaders (units) + Data (16B)Returns requested data or write status
  • Initialization: During link configuration (via InitFC1 and InitFC2 DLLPs), receiver advertises total buffer credits for each of the 6 pools (PH, PD, NPH, NPD, CplH, CplD).
  • Credit Consumption: Transmitter maintains counters: Credits_Consumed = Credits_Consumed + Packet_Cost.
  • Credit Replenishment: As the receiver processes TLPs and frees FIFO space, it transmits UpdateFC DLLPs. The transmitter updates Credits_Limit. Transmission stalls if Credits_Consumed > Credits_Limit.

9. Frequently Asked Questions (PCIe Engineering FAQ)

What is the difference between a TLP and a DLLP?

TLP (Transaction Layer Packet): Generated by the Transaction Layer to carry user and host data (Memory Reads, Memory Writes, Completions, Configuration accesses). TLPs contain a 3DW or 4DW header, up to 4096 bytes of payload, and an optional 32-bit ECRC. TLPs are protected across the physical link with a 12-bit sequence number and 32-bit LCRC.

DLLP (Data Link Layer Packet): Generated and consumed entirely within the Data Link Layer (Layer 2). DLLPs are fixed at 6 bytes (or 8 bytes in FLIT mode) and never enter the Transaction Layer. They carry link management data: ACK/NAK packet acknowledgments, Flow Control credit initializations (InitFC1, InitFC2), and Flow Control updates (UpdateFC).

Why did PCIe Gen 3 switch from 8b/10b to 128b/130b encoding?

Gen 1 and Gen 2 used 8b/10b encoding, where every 8 bits of payload data required 10 bits transmitted across the physical wire. This represented an enormous 20% bandwidth overhead.

In Gen 3, the PCI-SIG switched to 128b/130b encoding combined with polynomial scrambling (LFSR). In 128b/130b, 128 data bits are prefixed with only a 2-bit synchronization header (01b for data, 10b for ordered sets), slashing line overhead to just 1.54%. This enabled Gen 3 at 8.0 GT/s to effectively double the true payload throughput of Gen 2 (5.0 GT/s) without needing a 10 GT/s clock.

What is PCIe Equalization (EQ) in Gen 3, 4, 5, and 6?

As transmission frequencies reach multi-gigahertz, high-frequency signal components attenuate much faster than low frequencies over PCB copper traces, causing severe Inter-Symbol Interference (ISI) and closing the eye diagram.

PCIe Equalization is a 4-phase closed-loop hardware tuning procedure executed during LTSSM Recovery:
• Phase 0 & 1: Upstream and downstream ports exchange default presets (P0–P10).
• Phase 2: Upstream port adjusts Transmitter Feed-Forward Equalization (FFE: Pre-shoot, Main cursor, De-emphasis) based on downstream receiver requests.
• Phase 3: Downstream port tunes its transmitter coefficients while receiver CTLE (Continuous Time Linear Equalization) and DFE (Decision Feedback Equalization) adapt to optimize the eye opening.

Can a PCIe x4 device work in a physical x16 slot?

Yes. PCIe has complete forward and backward mechanical and electrical interoperability. During link training (LTSSM Configuration), the Root Complex and Endpoint discover available lanes and automatically negotiate link width down to x4. The unused 12 lanes remain electrically idle, and the device runs at full x4 speed without any software or driver intervention.

What is PCIe FLIT mode and why was it introduced in Gen 6?

Historically, PCIe TLPs were variable-length packets framed by physical start and end tokens (STP/END). In Gen 6 (64 GT/s), PCIe adopted PAM4 signaling, which quadrupled bit errors, making traditional ACK/NAK retransmission inefficient.

FLIT (Flow Control Unit) Mode standardizes all transfers into fixed 256-byte blocks. Each FLIT contains 242 bytes of TLP payload, 6 bytes of Data Link Layer protocol data, and 8 bytes of low-latency Forward Error Correction (FEC). The receiver uses FEC to instantly correct bit errors in real time, guaranteeing low latency and high bandwidth.
