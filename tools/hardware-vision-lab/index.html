Complete Hardware Vision Pipeline Architecture

How pixel streams traverse dual on-chip BRAM line buffers, latch into the 3×3 sliding window register array, feed the 0-DSP shift-add arithmetic tree, and update the autonomous bounding box tracker without CPU intervention.

150 MHz Clock 1 Pixel / Cycle
STAGE 1: LINE BUFFERS

Dual BRAM FIFOs (Zero DDR Overhead)

Traditional CPU or GPU image processing requires copying every video frame into external DDR DRAM, creating severe memory bus congestion. This FPGA pipeline stores only 2 horizontal scanlines (2 × 480 bytes = 960 Bytes) in dual on-chip Block RAMs.

On every clock tick, the newest pixel is written into FIFO 0, the read-out byte from FIFO 0 enters FIFO 1, and FIFO 1 outputs the pixel from 2 rows ago. This produces 3 vertically aligned pixels (Row Y, Row Y-1, Row Y-2) in parallel without DDR access.

On-Chip SRAM Required: 960 Bytes (< 1 BRAM tile)
STAGE 2: WINDOW MATRIX

3×3 Sliding Window (9 Shift Registers)

To compute 2D convolution, the chip needs a 3×3 pixel neighborhood surrounding each coordinate. Instead of reloading data, 9 D-Flip-Flops (p00 through p22) form a spatial shift matrix.

On each rising clock edge, the 3 new incoming bytes from the line buffer taps latch into column 2 (p02, p12, p22) while column 2 shifts into column 1, and column 1 into column 0. All 9 pixels are simultaneously available to combinational arithmetic gates every clock tick.

Register Count: 9 × 8-bit = 72 Flip-Flops
STAGE 3: PARALLEL MAC

0-DSP Multipliers (Bit-Shift Adder Tree)

The Sobel convolution kernels have fixed integer weights: [-1, 0, 1] and [-2, 0, 2]. In silicon, multiplying by 2 is accomplished by shifting wires left by 1 bit (p << 1), which requires zero transistors and zero DSP blocks.

A balanced 3-stage adder tree computes horizontal gradient Gx and vertical gradient Gy in parallel, adds absolute values |Gx| + |Gy| (Manhattan distance), and compares against the threshold in a single clock cycle.

Arithmetic Hardware: 0 DSP Multipliers (Pure Adders)
STAGE 4: BOUNDING BOX

Autonomous Tracker (Zero CPU Interrupts)

While software object trackers require OpenCV bounding-box algorithms that stall the CPU, this silicon architecture uses 4 concurrent hardware comparators running at 150 MHz.

Whenever the convolution engine flags an active edge pixel at coordinate (X, Y), the registers conditionally update: x_min = min(x_min, X), x_max = max(x_max, X), y_min = min(y_min, Y), and y_max = max(y_max, Y). At vertical sync (VSYNC), the bounding box is latched with zero CPU latency.

Tracking Latency: 0 Cycles (Instantly on VSYNC)
STAGE 5: LATENCY BUDGET

Pipeline Latency & Throughput Analysis

The total latency from the first camera pixel entering the chip to the first processed edge pixel leaving the chip is exactly 2 scanlines + 4 clock cycles (the time needed to fill both line buffers and propagate through the 3-stage adder tree).

Once the pipeline is primed, the hardware achieves a 100% duty cycle: exactly 1 processed pixel is produced on every single rising clock edge without pipeline bubbles, easily sustaining 1080p @ 60 FPS (124.8 MHz pixel clock) or 720p @ 120 FPS.

Sustained Throughput: 150 Mpixels / sec (1 Pixel/Cycle)

Frequently Asked Questions


    

      
What is the latency of this hardware image processing pipeline?

      

        The latency is exactly 2 image lines + 4 clock cycles. The hardware must buffer the first 2 horizontal scanlines before the 3×3 matrix is valid. Once filled, it streams 1 processed pixel on every single rising clock edge without stalling.
      

    


    

      
Why does the Sobel operator require 0 DSP multipliers?

      

        The Sobel kernel contains coefficients [-1, 0, 1] and [-2, 0, 2]. Multiplying an 8-bit integer by 2 is accomplished in digital logic by shifting the bit vector left by 1 position (p << 1), which requires zero transistors. The entire convolution is implemented with a lightweight 3-stage adder tree.
