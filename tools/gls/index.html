The Complete Engineering Guide to Gate-Level Simulation (GLS)

      
Master the principles, industry workflows, standard cell modeling, and signoff verification practices behind post-synthesis and post-layout ASIC simulation.

    


    

      
      

        
🔬 1. What is Gate-Level Simulation?

        

          Gate-Level Simulation (GLS) is the verification methodology where a circuit is simulated not as behavioral, high-level code, but as a discrete netlist of mapped foundry standard cells (AND, NAND, MUX, DFF) and interconnect wires.
        

        
    
          
  • Input: Synthesized gate netlist (.v) + Standard Cell Simulation Models + Testbench (.v) + Optional SDF.
    • 
          
  • Significance: Acts as the ultimate sanity check that logic synthesis did not alter circuit semantics or introduce synthesis-simulation mismatches.
    • 
        

      


      
      

        
⚡ 2. Why RTL Sim is Not Enough

        

          High-level RTL simulation executes ideal Zero-Delay mathematical evaluations. However, real physical silicon experiences real hardware constraints:
        

        
    
          
  • X-Propagation: RTL can artificially hide uninitialized hardware registers due to optimistic ternary operators.
    • 
          
  • Reset Race Conditions: Asynchronous reset de-assertion edges can violate recovery/removal timing.
    • 
          
  • Dynamic Hazards & Glitches: Reconvergent logic paths cause transient glitches that consume dynamic power or latch false data.
    • 
        

      


      
      

        
📦 3. Standard Cell Simulation Models

        

          Unlike RTL operators (+, -, *), standard cells (e.g. sky130_fd_sc_hd__dfrtp_1) do not exist natively in Icarus Verilog or VCS.
        

        
    
          
  • Verilog Primitives: Models define UDPs (User Defined Primitives) or Boolean gate logic for each foundry cell.
    • 
          
  • Specify Blocks: Contain pinpoint timing arcs (A => X) = (min:typ:max) and timing checks ($setup, $hold, $width).
    • 
          
  • Zero Unresolved Cells: Every instance must match a validated cell model.
    • 
        

      


      
      

        
⏱️ 4. Zero-Delay vs Timing-Aware GLS

        

          GLS verification is deployed in two distinct operational phases during the ASIC design cycle:
        

        
    
          
  • Zero-Delay GLS (Δt = 0): Verifies logical equivalence post-synthesis and confirms proper reset sequencing without race delays.
    • 
          
  • Timing-Aware GLS: Back-annotates SDF file delays from parasitic extraction (RCX) to observe actual physical propagation times and catch hold-time races.
    • 
        

      


      
      

        
📐 5. Post-Synthesis vs Post-Layout GLS

        

          The ASIC implementation flow utilizes two tiers of Gate-Level Simulation:
        

        
    
          
  • Post-Synthesis GLS: Executed immediately after Yosys or Design Compiler logic synthesis. Verifies technology mapping and scan chain insertion.
    • 
          
  • Post-Layout GLS: Executed after Clock Tree Synthesis (CTS) and Detailed Routing. Uses real parasitic wire delays to verify clock skew and setup/hold signoff.
    • 
        

      


      
      

        
🚨 6. Common GLS Failure Modes

        

          Engineers frequently encounter critical discrepancies during gate simulation:
        

        
    
          
  • X-Pessimism: Standard cell flip-flops output unknown 'X' if setup/hold is violated or if reset is not asserted before clocking.
    • 
          
  • Multi-Cycle & False Paths: In timing-aware GLS, multi-cycle paths will report false timing violations unless suppressed with SDC constraints.
    • 
          
  • Glitches on Asynchronous Pins: Combinational hazard glitches arriving at an asynchronous clear pin can inadvertently reset the chip.
    •

Frequently Asked Questions (FAQ)


    

      

        Why does my GLS simulation output red 'X' states while my RTL simulation passes?
        +
      

      

        In behavioral RTL, if a variable is used in an if (sel) statement when sel=0, the branch executes without evaluating whether the other branch is known. However, in gate netlists, standard cell flip-flops power up in an unknown state (1'bx). If your circuit lacks a clean power-on reset or if a flip-flop's enable pin remains uninitialized, the 'X' will propagate throughout the sequential state logic, alerting you to a genuine hardware startup flaw.
      

    


    

      

        What is SDF timing back-annotation?
        +
      

      

        Standard Delay Format (SDF) is an IEEE standard text format containing accurate interconnect delays and gate propagation delays extracted from physical layout parasitic extraction (SPEF/RCX) and Static Timing Analysis (OpenSTA). By calling $sdf_annotate("file.sdf", dut); in the testbench, the simulator replaces default gate timing with calibrated post-layout delays.
      

    


    

      

        Why is GLS required if Static Timing Analysis (STA) already proves timing?
        +
      

      

        Static Timing Analysis (STA) verifies that every static timing path satisfies setup and hold constraints under mathematical clock domains. However, STA does not simulate functional vector behavior! GLS is crucial to verify asynchronous clock domain crossing (CDC) synchronizers, power-on reset sequencing, PLL lock-in behavior, multi-cycle path functional safety, and software-driven boot sequences.
      

    


    

      

        How does SkyWater SKY130 HD model gate delays in Icarus Verilog?
        +
      

      

        SkyWater SKY130 HD simulation models embed Verilog specify ... endspecify blocks. Inside each specify block, pin-to-pin timing arcs define the minimum, typical, and maximum delay for transitions: for example (A => X) = (0.10:0.14:0.19) specifies a 100ps minimum, 140ps typical, and 190ps maximum propagation delay through an AND gate.
