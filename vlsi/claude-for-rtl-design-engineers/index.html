Chapter 01

The ASIC Engineer's Mental Model for AI

🧠 Silicon Reality vs. Statistical Prediction

In software engineering, a typo or off-by-one bug can be patched in production within minutes via a container push. In ASIC semiconductor design, an undetected RTL bug results in a $5M–$20M metal-spin or full-mask respin, a 6–9 month schedule slip, and catastrophic market window loss.

Large Language Models (LLMs) like Claude 3.5 Sonnet are fundamentally probabilistic token prediction engines trained on massive corpora of syntax and technical prose. They possess extraordinary structural knowledge of SystemVerilog grammar, AMBA bus protocol standards, and SVA syntax. However:

⚠️ Non-Negotiable ASIC Engineering Reality
Claude has no physics engine. It cannot calculate non-linear interconnect RC delays, evaluate 3nm FinFET quantum tunneling leakage, or run a deterministic boolean SAT solver. It predicts what valid Verilog looks like, not what physical silicon does.

To use Claude effectively as a Principal RTL Architect, you must adopt the Three-Tier ASIC AI Verification Contract:

Tier Actor Primary Responsibility Deterministic Authority
Tier 1: Generation & Review Claude / Claude Code Scaffolding, protocol translation, lint diagnosis, SVA synthesis, prompt-driven code review Zero Sign-Off Authority (Advisory Only)
Tier 2: Verification & Implementation EDA Tool Suite (VCS, Questa, JasperGold, Genus, DC, SpyGlass) Exhaustive random simulation, static lint, CDC verification, formal equivalence, technology mapping, STA sign-off 100% Mathematical & Physical Proof
Tier 3: Sign-Off & Tapeout Human Principal Engineer / ASIC Architect Microarchitecture validation, constraint sign-off, waiver review, silicon tapeout sign-off Final Legal & Technical Accountability

Common AI Failure Modes in Semiconductor Design

Every front-end engineer must guard against these specific failure modes:

  • Phantom Port Generation: In multi-module instantiations, Claude may invent plausible-looking signals (e.g., axi_awqos, bvalid_ack) that do not exist in your team's frozen IP interface.
  • Silent Vector Truncation: In complex arithmetic expressions, mixing logic [31:0] with implicit 32-bit signed integers can silently drop MSBs or invert signedness without generating a compiler error.
  • Inferred Latches via Incomplete Branches: Claude frequently omits default assignments in deeply nested if-else or case structures, creating level-sensitive latches that wreck scan ATPG and STA closure.
  • Hallucinated Tool Commands & SDC Options: Asking Claude for Cadence Genus or Synopsys PrimeTime commands can yield synthesized flag names (e.g., set_clock_groups -exclusive_async) that fail during batch EDA runs.

module counter_buggy (
    input  wire        clk, rst_n, en,
    input  wire signed [7:0] offset,
    output logic [7:0] count
);
    // BUG 1: Incomplete combinational logic infers latch
    logic [7:0] next_count;
    always_comb begin
        if (en)
            next_count = count + offset; // BUG 2: mixed signed/unsigned arithmetic
        // Missing else -> INFERRED LATCH
    end

    // BUG 3: Blocking assignment in clocked procedural block
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            count = 8'h00; // Blocking assignment in sequential logic!
        else
            count = next_count;
    end
endmodule

// ✅ CORRECTED SYSTEMVERILOG: Latch-free, non-blocking, explicit signedness
module counter_clean (
    input  logic             clk,
    input  logic             rst_n,
    input  logic             en,
    input  logic signed [7:0] offset,
    output logic signed [7:0] count
);
    logic signed [7:0] next_count;

    // Explicit default prevents latches
    always_comb begin
        next_count = count;
        if (en) begin
            next_count = count + offset;
        end
    end

    // Strict non-blocking sequential assignments
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            count <= 8'sd0;
        end else begin
            count <= next_count;
        end
    end
endmodule

03. AMBA Protocol Implementation & Ready/Valid Handshakes

Bus protocols (AXI4, AXI4-Lite, APB4) govern on-chip communication in modern SoCs. Protocol compliance errors are notoriously difficult to debug after synthesis.

ARM AXI Golden Rule
A sender's VALID signal must NEVER depend combinationally on the receiver's READY signal. Doing so creates circular combinational loops across IP blocks, causing system deadlocks. However, READY may wait for VALID.

When registering READY to break long timing paths, a standard single flip-flop causes a 1-cycle throughput penalty (50% maximum bandwidth). To achieve 100% throughput with fully registered inputs and outputs, a Skid Buffer is required. Claude can generate and verify skid buffers across AXI channels.

04. FIFO and Asynchronous Clock Domain Crossing Design

FIFOs decouple data producer and consumer rates. Dual-clock Asynchronous FIFOs cross data between asynchronous clock domains using Gray-code pointers.

  • Gray Code Property: Successive Gray-code values differ by exactly one bit, preventing multi-bit bus skew hazards when sampled by 2-FF synchronizers.
  • Pointer Math: For a FIFO of depth 2^N, pointers must be N+1 bits wide. The extra MSB distinguishes a completely full FIFO from an empty FIFO when the bottom N bits match.
  • Safe Empty Condition: Evaluated in the Read Clock domain:
    assign empty = (rptr_gray == wptr_gray_sync);
  • Safe Full Condition: Evaluated in the Write Clock domain by checking inverted top 2 MSBs:
    assign full = (wptr_gray == {~rptr_gray_sync[N:N-1], rptr_gray_sync[N-2:0]});

05. Finite State Machine (FSM) Optimization & Encoding

State encoding directly impacts area, critical path timing, and dynamic power dissipation. Claude helps evaluate trade-offs:

Encoding Type Flip-Flops Required Combinational Decode Depth Best Used For
Binary (Sequential) ceil(log2(S)) (Minimum) Moderate to Deep (multi-bit comparator) Area-constrained control blocks, low-speed interfaces
One-Hot S (1 flop per state) Minimal (Single gate per state test) High-speed ASIC pipelines (>1 GHz), FPGAs
Gray Code ceil(log2(S)) Low to Moderate Adjacent state sequences, low-power state transitions

Claude can convert 1-process FSMs into industry-standard 3-process FSMs (State FF, Combinational Next-State, and Registered Outputs) to guarantee glitch-free control outputs without combinational timing penalties.

06. Clock & Reset Domain Crossing (CDC / RDC) Analysis

Metastability cannot be eliminated; it can only be bounded to acceptable Mean Time Between Failures (MTBF > 1000 years).

  • Single-Bit CDC: Safe with 2-FF or 3-FF synchronizers (using standard cell synchronizer library cells like SYNC2_X1).
  • Multi-Bit CDC Hazard: Never run multi-bit binary buses through independent synchronizers. Interconnect net delay differences (bus skew) cause bits to be sampled on different clock cycles, transmitting illegal intermediate values.
  • Reset Deassertion Metastability: While reset assertion can be asynchronous, reset release must be synchronous to the clock to prevent flip-flops from entering metastability if reset deasserts within the setup/hold window.
CDC Sign-off Mandate
RTL review by Claude is an early-filtering filter. It does NOT replace structural and functional CDC verification via Siemens Questa CDC or Synopsys VC CDC.

08. Synthesis QoR and STA Timing Path Interpretation

When a synthesis run fails timing with negative slack (WNS < 0), the RTL engineer must inspect the gate-level critical path report and map it back to RTL structures.

STA Report Symptom Underlying Hardware Bottleneck RTL Architectural Fix
High Logic Depth (>25 gates in 1GHz clock) Unpipelined arithmetic (e.g. Add → Multiply → Compare in 1 cycle) Insert pipeline stage (register retiming) between arithmetic ops
High Cell Fanout (>64 loads) Global control signal driving hundreds of multiplexers or enables Duplicate control registers in RTL (register replication)
Mux Cascade Delay Deep priority if-else tree on wide bus Refactor into parallel one-hot multiplexer or balanced tree

09. Formal Verification & SystemVerilog Assertions (SVA)

Formal Property Verification (FPV) in tools like Cadence JasperGold or Synopsys VC Formal mathematically proves that a design satisfies properties across all possible input scenarios without writing a testbench.

  • Assume (assume property): Constrains environment inputs (e.g., "The upstream block will never assert read when empty").
  • Assert (assert property): Proves internal design guarantees (e.g., "FIFO pointers will never overflow").
  • Cover (cover property): Proves that a target scenario is reachable (e.g., "FIFO reaches full state within 20 cycles").

10. Low-Power RTL and IEEE 1801 UPF Separation

Modern SoCs utilize aggressive low-power techniques: dynamic clock gating, multi-voltage islands, power gating, and state retention.

Clean Division: RTL vs. UPF
What belongs in RTL: Functional enable signals, power management state machine sequencers, and handshake logic.
What belongs in UPF (Unified Power Format): Power switches, level shifters, isolation strategies, and retention cell mapping. Never instantiate physical isolation NAND/NOR gates manually in functional RTL.

11. RTL Refactoring and PPA (Power-Performance-Area) Optimization

PPA optimization requires eliminating redundant logic while preserving cycle-exact interface timing.

  • Operator Sharing: Sharing expensive 32-bit adders or multipliers across mutually exclusive branches.
  • Common Subexpression Elimination: Pre-calculating identical address offsets.
  • Clock Gating Readiness: Ensuring register load enables have low activity factors so synthesis tools can automatically insert Integrated Clock Gating (ICG) cells.

12. Waveform and Simulation Regression Debugging

When regression testbenches fail, debugging requires correlating signal transitions across time. Claude can analyze ASCII signal tables or VCD excerpts to pinpoint race conditions and off-by-one pointer errors.

# RTL Code Review Skill for ASIC Front-End Engineers

## Purpose
Performs comprehensive static architectural and syntactic review of SystemVerilog/Verilog RTL modules before synthesis and simulation, flagging race conditions, inferred latches, multi-driver nets, and non-synthesizable constructs.

## When to Activate
Activate when an engineer provides a SystemVerilog module for code quality inspection, pre-commit audit, or lint-preparation review.

## Required Inputs
- SystemVerilog/Verilog source code (`.sv` or `.v`)
- Target technology context (ASIC standard cell vs FPGA)
- Clock and reset convention (e.g., active-low asynchronous reset, synchronous reset)
- Module interface specification (optional but recommended)

## Step-by-Step Workflow
1. **Header & Interface Audit:** Verify port directions, explicit bit-widths (avoid bare integers), unpacked dimensions, and package imports.
2. **Procedural Block Verification:**
   - Confirm sequential logic strictly uses `always_ff @(posedge clk or negedge rst_n)` with non-blocking assignments (`<=`).
   - Confirm combinational logic strictly uses `always_comb` with blocking assignments (`=`).
   - Confirm latches are never inferred unless intentionally declared via `always_latch`.
3. **Branch Completeness & Default Assignment:**
   - Verify every conditional branch (`if-else`, `case`) has an exhaustive default assignment or complete coverage to prevent unintended latches.
   - For `case` statements, verify `unique case` or `priority case` usage matches designer intent.
4. **Data Type & Arithmetic Sanity:**
   - Check signed vs unsigned operations: ensure mixed signed/unsigned arithmetic is explicitly cast with `$signed()`.
   - Audit bit-slice assignments and vector truncations.
5. **Synthesis & Simulation Antipatterns:**
   - Flag simulation delays (`#1`), initial blocks (outside simulation testbenches), and unsynthesizable system functions (`$display`, `$finish` inside synthesizable modules).
6. **Generate Structured Review Report:** Output categorized findings (Critical, Warning, Informational).

## Technical Constraints
- Never alter interface port names, signal widths, or cycle latency without explicit permission.
- Never assume an undeclared signal is 1 bit; flag explicit declarations.
- Distinguish between FPGA block RAM templates and ASIC flip-flop banks.

## Output Format
- **Executive Summary:** Pass/Needs Revision verdict.
- **Critical Issues (Must Fix):** Race conditions, inferred latches, multi-driver nets.
- **Warnings (Review Needed):** Truncation, signedness, default branches.
- **Suggested Corrected RTL:** Full synthesizable code block with line-by-line diff.

## Validation Checklist
- [ ] No blocking assignments in `always_ff`.
- [ ] No non-blocking assignments in `always_comb`.
- [ ] No inferred latches.
- [ ] Reset values provided for all sequential state registers.
- [ ] No multi-driver nets.

- **Recommended Waiver Directives:** If applicable, formatted for SpyGlass / Verilator.

# FIFO Design Review Skill

## Purpose
Audits dual-clock and single-clock FIFO implementations for pointer math correctness, empty/full detection, almost-empty/almost-full watermarks, circular memory wrap-around, and CDC safety.

## When to Activate
Activate when designing, verifying, or debugging FIFO buffers, queue controllers, or latency bridges.

## Required Inputs
- FIFO SystemVerilog source code
- Clock domain specifications (Synchronous single-clock vs Asynchronous dual-clock)
- Depth and Data Width parameters
- Watermark requirements (programmable empty/full threshold levels)

## Step-by-Step Workflow
1. **Pointer Dimensioning:** Confirm pointer width is $N+1$ where Depth = $2^N$ to distinguish full from empty.
2. **Gray Code Conversion Audit (Async FIFO):**
   - Verify binary-to-Gray conversion: `assign gray_ptr = bin_ptr ^ (bin_ptr >> 1)`.
   - Verify Gray-to-binary conversion logic in the destination domain.
   - Confirm Gray pointers are registered before crossing clock boundaries.
3. **Synchronizer Chain Verification:**
   - Confirm 2-stage (or 3-stage) flip-flop synchronizers exist on pointer crossings.
   - Check for `(* ASYNC_REG = "TRUE" *)`, `set_false_path`, or `set_max_delay -datapath_only` constraint requirements.
4. **Full and Empty Flag Generation:**
   - Empty: `assign empty = (rptr_gray == wptr_gray_sync)` in read domain.
   - Full: Verify top two MSBs inverted with lower bits identical: `assign full = (wptr_gray == {~rptr_gray_sync[N:N-1], rptr_gray_sync[N-2:0]})`.
5. **Simultaneous Push/Pop Hazards:** Check behavior when `wr_en` and `rd_en` assert concurrently under edge conditions.
6. **Watermark / Level Counter Accuracy:** Audit almost-full and almost-empty calculations for one-cycle latency offset.

## Technical Constraints
- Non-power-of-2 depth asynchronous FIFOs require specialized Gray coding or dual-pointer math; flag non-$2^N$ depth as a critical CDC risk.

## Output Format
- **Architecture Assessment:** Synchronous vs Asynchronous assessment.
- **Pointer & Synchronizer Audit:** Detailed analysis of pointer generation and CDC path.
- **Flag Correctness Review:** Mathematical verification of empty/full formulas.
- **SVA Assertions:** SystemVerilog assertions to prove safety.

## Validation Checklist
- [ ] Pointer width is $\log_2(	ext{DEPTH}) + 1$.
- [ ] Gray code changes by only 1 bit per increment.
- [ ] Full condition verified in write clock domain.
- [ ] Empty condition verified in read clock domain.
- [ ] Write into full and read from empty are strictly prevented.

# Clock & Reset Domain Crossing (CDC/RDC) Review Skill

## Purpose
Identifies asynchronous timing hazards, metastability risks, multi-bit coherency bugs, reconvergence artifacts, and reset assertion/deassertion vulnerabilities in multi-clock ASIC SoCs.

## When to Activate
Activate when analyzing multi-clock RTL, async reset distribution, or preparing for Questa CDC / Synopsys VC CDC signoff.

## Required Inputs
- Multi-clock SystemVerilog RTL modules
- Clock definition list (clock frequencies, domains, asynchronous relationships)
- Reset architecture (asynchronous assert / synchronous deassert scheme)

## Step-by-Step Workflow
1. **Clock Domain Identification:** Map every flip-flop to its originating clock tree.
2. **Single-Bit Crossing Audit:**
   - Ensure multi-flop synchronizers (2-FF / 3-FF) are deployed on all async control signals.
   - Verify pulse synchronizers (toggle-type) for fast-to-slow clock domain pulses.
3. **Multi-Bit Crossing Audit (Crucial):**
   - Check for unsafe multi-bit CDC: Flag any instance where individual bits of a binary bus cross through separate synchronizers.
   - Mandate Gray code conversion, asynchronous FIFO, or Valid/Ready 4-phase handshake synchronizer.
4. **Reconvergence Analysis:**
   - Detect signals that cross asynchronously, synchronize separately, and subsequently converge into common combinational logic.
5. **Reset Domain Crossing (RDC):**
   - Check that asynchronous resets use an Asynchronous Assert, Synchronous Deassert (AASD) synchronizer per clock domain.
   - Check for reset race conditions on sequential circuits during power-up/wake-up.

## Technical Constraints
- Never declare a CDC path "clean" based solely on simulation or code inspection. State clearly that Questa CDC / VC CDC / SpyGlass CDC and SDC constraints (`set_clock_groups -asynchronous`) are mandatory for sign-off.

## Output Format
- **Domain Topology Table:** Clock A -> Clock B | Signal Name | Synchronizer Topology | Hazard Status
- **Identified Hazards & Risks:** Explanation of potential failure modes (metastability, skew, reconvergence).
- **Hardened SystemVerilog Module:** Safe synchronizer implementation.
- **Synthesis/STA Directives:** Necessary false-path / max-delay constraints.

## Validation Checklist
- [ ] All async signals pass through dedicated synchronizers.
- [ ] No binary counters cross domains without Gray coding or handshaking.
- [ ] Reset release synchronized to destination clock edge.
- [ ] Synchronizer flip-flops marked with `DONT_TOUCH` and `ASYNC_REG`.

# APB & AXI Protocol Review Skill

## Purpose
Audits AMBA APB4, AXI4-Lite, and AXI4 bus interfaces for protocol compliance, deadlock freedom, zero-bubble throughput, skid buffer integration, and backpressure correctness.

## When to Activate
Activate when writing or inspecting memory-mapped bus interfaces, peripherals, crossbars, DMA controllers, or protocol converters.

## Required Inputs
- Protocol type (AMBA APB4, AXI4-Lite, AXI4 Full)
- Role (Master / Subordinate / Interconnect)
- SystemVerilog RTL source code
- Outstanding transaction / burst capability specifications

## Step-by-Step Workflow
1. **Handshake Rule Verification (AXI/AXI-Lite):**
   - Verify ARM AXI Rule: `VALID` signal must NEVER depend combinationally on `READY` (prevents deadlock).
   - Verify `READY` may depend on `VALID`.
   - Verify once `VALID` is asserted, payload and `VALID` remain asserted until `READY` is high (Handshake Stability Rule).
2. **APB4 Protocol Compliance:**

    input  logic [DATA_WIDTH-1:0]  PWDATA,
    input  logic [(DATA_WIDTH/8)-1:0] PSTRB,
    output logic                   PREADY,
    output logic [DATA_WIDTH-1:0]  PRDATA,
    output logic                   PSLVERR,

    // Hardware Sideband Signals
    input  logic [31:0]            hw_status_i,
    input  logic [31:0]            hw_irq_event_i,
    output logic [31:0]            ctrl_reg_o,
    output logic                   irq_o
);

    // Register Offsets
    localparam logic [ADDR_WIDTH-1:0] REG_CTRL     = 8'h00;
    localparam logic [ADDR_WIDTH-1:0] REG_STATUS   = 8'h04;
    localparam logic [ADDR_WIDTH-1:0] REG_IRQ_STAT = 8'h08;
    localparam logic [ADDR_WIDTH-1:0] REG_IRQ_EN   = 8'h0C;

    // Internal Registers
    logic [31:0] reg_ctrl;
    logic [31:0] reg_irq_stat;
    logic [31:0] reg_irq_en;

    // APB Transfer Detection (Setup phase -> Access phase)
    logic apb_write_trans;
    logic apb_read_trans;

    assign apb_write_trans = PSEL && PENABLE &&  PWRITE;
    assign apb_read_trans  = PSEL && PENABLE && !PWRITE;
    assign PREADY          = 1'b1; // Zero wait-state

    // Register Write Logic (Synchronous)
    always_ff @(posedge PCLK or negedge PRESETn) begin
        if (!PRESETn) begin
            reg_ctrl     <= 32'h0000_0000;
            reg_irq_stat <= 32'h0000_0000;
            reg_irq_en   <= 32'h0000_0000;
        end else begin
            // Hardware interrupt pulse capture
            reg_irq_stat <= reg_irq_stat | hw_irq_event_i;

            if (apb_write_trans) begin
                case (PADDR)
                    REG_CTRL: begin
                        for (int i = 0; i < 4; i++) begin
                            if (PSTRB[i]) reg_ctrl[i*8 +: 8] <= PWDATA[i*8 +: 8];
                        end
                    end
                    REG_IRQ_STAT: begin
                        // W1C: Writing 1 clears the corresponding interrupt bit
                        for (int i = 0; i < 4; i++) begin
                            if (PSTRB[i]) reg_irq_stat[i*8 +: 8] <= (reg_irq_stat[i*8 +: 8] & ~PWDATA[i*8 +: 8]);
                        end
                    end
                    REG_IRQ_EN: begin
                        for (int i = 0; i < 4; i++) begin
                            if (PSTRB[i]) reg_irq_en[i*8 +: 8] <= PWDATA[i*8 +: 8];
                        end
                    end
                    default: ; // Unmapped address write triggers PSLVERR
                endcase
            end
        end
    end

    // Combinational Read Multiplexer & Error Response
    always_comb begin
        PRDATA  = 32'h0000_0000;
        PSLVERR = 1'b0;

        if (PSEL) begin
            case (PADDR)
                REG_CTRL:     PRDATA = reg_ctrl;
                REG_STATUS:   PRDATA = hw_status_i; // Live HW status
                REG_IRQ_STAT: PRDATA = reg_irq_stat;
                REG_IRQ_EN:   PRDATA = reg_irq_en;
                default: begin
                    PRDATA  = 32'hDEAD_BEEF;
                    PSLVERR = 1'b1; // Error on unmapped address
                end
            endcase
        end
    end

    assign ctrl_reg_o = reg_ctrl;
    assign irq_o      = |(reg_irq_stat & reg_irq_en);

endmodule

Project C Dual-Clock Asynchronous FIFO with Gray-Code Pointers

1. Specification: Safe clock domain crossing between independent write and read clocks using $N+1$ bit Gray-code pointers and 2-stage synchronizers.

async_fifo.sv
SystemVerilog RTL 
module async_fifo #(
    parameter int DWIDTH = 64,
    parameter int DEPTH  = 16 // Must be 2^N
)(
    input  logic              wclk,
    input  logic              wrst_n,
    input  logic              wr_en,
    input  logic [DWIDTH-1:0] wdata,
    output logic              wfull,

    input  logic              rclk,
    input  logic              rrst_n,
    input  logic              rd_en,
    output logic [DWIDTH-1:0] rdata,
    output logic              rempty
);
    localparam int AWIDTH = $clog2(DEPTH);

    logic [AWIDTH:0] wptr_bin, wptr_gray, wptr_gray_sync1, wptr_gray_sync2;
    logic [AWIDTH:0] rptr_bin, rptr_gray, rptr_gray_sync1, rptr_gray_sync2;
    logic [DWIDTH-1:0] mem [0:DEPTH-1];

    // Dual-Port RAM Write
    always_ff @(posedge wclk) begin
        if (wr_en && !wfull)
            mem[wptr_bin[AWIDTH-1:0]] <= wdata;
    end

    // RAM Read (unregistered output)
    assign rdata = mem[rptr_bin[AWIDTH-1:0]];

    // Binary to Gray Helper
    function automatic logic [AWIDTH:0] bin2gray(input logic [AWIDTH:0] b);
        return b ^ (b >> 1);
    endfunction

    // Write Domain Logic
    always_ff @(posedge wclk or negedge wrst_n) begin
        if (!wrst_n) begin
            wptr_bin  <= '0;
            wptr_gray <= '0;
        end else if (wr_en && !wfull) begin
            wptr_bin  <= wptr_bin + 1'b1;
            wptr_gray <= bin2gray(wptr_bin + 1'b1);
        end
    end

    // Read Pointer Synchronizer into Write Domain (2-FF)
    always_ff @(posedge wclk or negedge wrst_n) begin
        if (!wrst_n) begin
            rptr_gray_sync1 <= '0;
            rptr_gray_sync2 <= '0;
        end else begin
            rptr_gray_sync1 <= rptr_gray;
            rptr_gray_sync2 <= rptr_gray_sync1;
        end
    end

    // Write Full Generation
    assign wfull = (wptr_gray == {~rptr_gray_sync2[AWIDTH:AWIDTH-1], rptr_gray_sync2[AWIDTH-2:0]});

    // Read Domain Logic
    always_ff @(posedge rclk or negedge rrst_n) begin
        if (!rrst_n) begin
            rptr_bin  <= '0;
            rptr_gray <= '0;
        end else if (rd_en && !rempty) begin
            rptr_bin  <= rptr_bin + 1'b1;
            rptr_gray <= bin2gray(rptr_bin + 1'b1);
        end
    end

    // Write Pointer Synchronizer into Read Domain (2-FF)
    always_ff @(posedge rclk or negedge rrst_n) begin
        if (!rrst_n) begin
            wptr_gray_sync1 <= '0;
            wptr_gray_sync2 <= '0;
        end else begin
            wptr_gray_sync1 <= wptr_gray;
            wptr_gray_sync2 <= wptr_gray_sync1;
        end
    end

    // Read Empty Generation
    assign rempty = (rptr_gray == wptr_gray_sync2);

endmodule

module axi_skid_buffer #(
    parameter int DATA_WIDTH = 32
)(
    input  logic                  clk,
    input  logic                  rst_n,

    // Ingress Interface
    input  logic                  s_valid,
    output logic                  s_ready,
    input  logic [DATA_WIDTH-1:0] s_data,

    // Egress Interface
    output logic                  m_valid,
    input  logic                  m_ready,
    output logic [DATA_WIDTH-1:0] m_data
);

    // Internal Storage: Primary Output Register & Skid Register
    logic [DATA_WIDTH-1:0] reg_data, skid_data;
    logic                  reg_valid, skid_valid;

    // Upstream ready when skid buffer is unoccupied
    assign s_ready = !skid_valid;

    // Downstream output
    assign m_valid = reg_valid;
    assign m_data  = reg_data;

    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            reg_valid  <= 1'b0;
            skid_valid <= 1'b0;
            reg_data   <= '0;
            skid_data  <= '0;
        end else begin
            // If downstream accepts current data
            if (m_ready) begin
                if (skid_valid) begin
                    // Drain skid buffer to main register
                    reg_valid  <= 1'b1;
                    reg_data   <= skid_data;
                    skid_valid <= 1'b0;
                end else begin
                    // Pass-through new incoming data
                    reg_valid  <= s_valid;
                    reg_data   <= s_data;
                end
            end else begin
                // Downstream is stalled (backpressure active)
                if (s_valid && s_ready) begin
                    // Store incoming transaction in skid buffer
                    skid_valid <= 1'b1;
                    skid_data  <= s_data;
                end
            end
        end
    end

module pwr_seq_fsm (
    input  logic clk,
    input  logic rst_n,
    input  logic pwr_down_req_i,
    input  logic pwr_up_req_i,
    input  logic pwr_switch_ack_i,

    output logic iso_en_o,
    output logic domain_rst_n_o,
    output logic pwr_switch_en_o,
    output logic clk_en_o,
    output logic pwr_status_idle_o
);

    typedef enum logic [2:0] {
        ST_ACTIVE    = 3'b000,
        ST_ISO_ON    = 3'b001,
        ST_RST_ASSERT= 3'b010,
        ST_PWR_OFF   = 3'b011,
        ST_OFF_IDLE  = 3'b100,
        ST_PWR_ON    = 3'b101,
        ST_RST_DEAS  = 3'b110,
        ST_ISO_OFF   = 3'b111
    } pwr_state_e;

    pwr_state_e state_q, state_d;

    // State Register
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) state_q <= ST_ACTIVE;
        else        state_q <= state_d;
    end

    // Next State Logic
    always_comb begin
        state_d = state_q;
        case (state_q)
            ST_ACTIVE:     if (pwr_down_req_i) state_d = ST_ISO_ON;
            ST_ISO_ON:     state_d = ST_RST_ASSERT;
            ST_RST_ASSERT: state_d = ST_PWR_OFF;
            ST_PWR_OFF:    if (pwr_switch_ack_i) state_d = ST_OFF_IDLE;
            ST_OFF_IDLE:   if (pwr_up_req_i) state_d = ST_PWR_ON;
            ST_PWR_ON:     if (pwr_switch_ack_i) state_d = ST_RST_DEAS;
            ST_RST_DEAS:   state_d = ST_ISO_OFF;
            ST_ISO_OFF:    state_d = ST_ACTIVE;
            default:       state_d = ST_ACTIVE; // Safe recovery
        endcase
    end

    // Registered Glitch-Free Outputs
    always_ff @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            iso_en_o           <= 1'b0;
            domain_rst_n_o     <= 1'b1;
            pwr_switch_en_o    <= 1'b1;
            clk_en_o           <= 1'b1;
            pwr_status_idle_o  <= 1'b1;
        end else begin
            case (state_d)
                ST_ACTIVE: begin
                    iso_en_o        <= 1'b0;
                    domain_rst_n_o  <= 1'b1;
                    pwr_switch_en_o <= 1'b1;
                    clk_en_o        <= 1'b1;
                end
                ST_ISO_ON: iso_en_o <= 1'b1;
                ST_RST_ASSERT: domain_rst_n_o <= 1'b0;
                ST_PWR_OFF, ST_OFF_IDLE: begin
                    pwr_switch_en_o <= 1'b0;
                    clk_en_o        <= 1'b0;
                end
                ST_PWR_ON: pwr_switch_en_o <= 1'b1;
                ST_RST_DEAS: begin
                    clk_en_o       <= 1'b1;
                    domain_rst_n_o <= 1'b1;
                end
                ST_ISO_OFF: iso_en_o <= 1'b0;
            endcase
        end
    end
endmodule

Engineering Security, IP Protection & NDA Compliance

🔒 Semiconductor IP Protection Mandate

Semiconductor intellectual property (RTL source, foundry PDKs, cell library characterization files, architecture specs) represents billions of dollars in enterprise value and is protected by severe legal Non-Disclosure Agreements (NDAs).

🚨 Zero-Tolerance AI Security Rules
  • Never paste unredacted proprietary RTL into public AI services: Consumer-tier LLM subscriptions frequently retain inputs for model training, violating foundry and client NDAs.
  • Verify Enterprise Zero Data Retention (ZDR): Only use enterprise Claude deployments covered by signed business associate agreements guaranteeing that inputs are never retained, logged, or used for model training.
  • Sanitized Anonymization: When asking Claude to debug a complex datapath, extract the mathematical topology into a generic, sanitized module (e.g., replace internal project codenames and bus widths with generic parameters).
  • Foundry PDK Secrecy: Never share foundry design rules (TSMC, Intel Foundry, Samsung, GlobalFoundries) or proprietary standard cell names (e.g., TSMC_N5_DFCNQD1) with external LLMs.

Frequently Asked Questions for RTL Engineers

Can Claude replace commercial ASIC synthesis tools like Synopsys DC or Cadence Genus? ▼
No. Claude is an LLM with no physical or electrical modeling engines. It cannot calculate non-linear interconnect RC delays, evaluate standard cell timing tables (.lib), or perform deterministic logic mapping. Claude functions as a front-end accelerator for generating and reviewing RTL before deterministic synthesis.
How do I prevent Claude from generating non-synthesizable SystemVerilog? ▼
Enforce strict constraints via your CLAUDE.md file: mandate IEEE 1800-2023 synthesizable constructs only (always_ff with non-blocking assignments, always_comb with blocking assignments, explicit reset conditions), strictly ban simulation constructs (#delays, initial blocks), and pass all generated code through Verilator or SpyGlass.
Can Claude guarantee Clock Domain Crossing (CDC) correctness? ▼
No. While Claude can write synchronizers and explain Gray code pointer math, code inspection alone cannot guarantee CDC sign-off. Silicon sign-off requires formal CDC tools (Questa CDC, VC CDC) with accurate SDC constraints to verify the absence of metastability, data reconvergence, and bus skew.
What are Claude Code skills and how do they benefit RTL teams? ▼
Claude Code skills are modular, version-controlled SKILL.md packages placed in your repository's .claude/skills/ directory. They define domain-specific workflows, mandatory coding standards, required input parameters, and validation checklists for tasks such as RTL code review, SVA generation, lint report triage, and timing report diagnosis.
How does an engineer debug synthesis timing violations with Claude? ▼
Extract the critical path report from Design Compiler or Genus (showing startpoint, cell delays, net delays, endpoint, and slack). Feed this report alongside the corresponding RTL module to Claude using the /timing-report-analysis skill. Claude will deconstruct the logic depth, identify high-fanout bottlenecks, and recommend architectural RTL fixes (e.g., register retiming, balanced multiplexer trees).
