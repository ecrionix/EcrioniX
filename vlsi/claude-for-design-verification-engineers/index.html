Module 1 · Engineering Core

Design Verification Fundamentals: Planning, Architectures & Closure

The Verification Bottleneck: Why DV Consumes 70% of Silicon R&D

In modern multimillion-gate System-on-Chip (SoC) engineering, design verification (DV) accounts for upwards of 65% to 75% of total project engineering hours. A single escaped functional bug that bypasses pre-silicon verification and reaches foundry fabrication costs upwards of $10M–$25M in mask re-spins, 6–9 months of schedule slippage, and catastrophic brand erosion.

Verification Paradigm Core Mechanism Primary Advantage Inherent Limitation
Directed Testing Engineer writes hand-crafted input vectors targeting explicit scenarios. Fast bring-up, simple to debug, verifies known happy-path functionality. Cannot uncover unforeseen corner cases ("unknown-unknowns"); prohibitive effort.
Constrained-Random (CRV) Solver generates randomized transactions bounded by legal protocol constraints. Explores billions of corner-case combinations automatically; high stress density. Requires self-checking scoreboards, complex testbenches, and functional coverage models.
Formal Property Checking Mathematical engines prove whether assertions hold across all reachable states. Exhaustive mathematical proof; discovers deep corner-case bugs in cycles. State-space explosion on large arithmetic datapaths; requires expert property authoring.

A Verification Plan (vPlan) is the contract between system architects, RTL designers, and verification engineers. Claude accelerates planning by extracting features, boundary conditions, and error injection modes from technical specifications:

SystemVerilog for Verification: OOP, Virtual Interfaces & Scheduling

Object-Oriented Programming (OOP) in Verification

Unlike synthesizable RTL (which models static spatial hardware structures), verification environments are dynamic software systems written in SystemVerilog (IEEE 1800). Key OOP concepts include:

  • Encapsulation: Grouping data members (`rand bit [31:0] addr;`) with methods (`function void print();`) and using `protected` or `local` visibility to guard internal state.
  • Inheritance (`extends`): Deriving specialized transaction classes from base classes (e.g. `axi_error_transaction extends axi_transaction`).
  • Polymorphism (`virtual` methods): Allowing testbenches to handle specialized objects via base class handles, dynamically binding method calls at runtime.
  • Deep Copy vs. Shallow Copy: Built-in object assignment (`b = new a;`) performs a shallow copy, duplicating primitive values but copying only pointers to sub-objects. Testbench objects must implement custom `do_copy()` methods to perform true deep copies of sub-handles.

Eliminating Simulation Race Conditions with Clocking Blocks

A common bug in naive SystemVerilog testbenches is the Read/Write race condition, where the testbench samples a DUT output in the same simulation delta-cycle that the DUT updates it. SystemVerilog solves this using the Stratified Event Queue and Clocking Blocks:

Event Region Execution Timing Testbench Activity
Preponed Before any events in the current time step occur. Input Sampling: Clocking blocks sample DUT inputs with #1step skew, capturing stable values prior to the active clock edge.
Active / NBA DUT clock triggers sequential logic update. DUT non-blocking assignments (<=) evaluate and update registers.
Observed After active and NBA regions settle. Concurrent SystemVerilog Assertions (SVA) evaluate properties.
Re-NBA Following Observed region. Output Driving: Clocking blocks drive output pins to the DUT (with #0 or output skew), guaranteeing zero race conditions.
tb/apb_if.sv (SystemVerilog Interface with Clocking Blocks) 
interface apb_if(input logic PCLK, input logic PRESETn);
  logic [31:0] PADDR;
  logic        PSEL;
  logic        PENABLE;
  logic        PWRITE;
  logic [31:0] PWDATA;
  logic [31:0] PRDATA;
  logic        PREADY;
  logic        PSLVERR;

  // Master Clocking Block: Sample in Preponed (#1step), Drive in Re-NBA (#1ns)
  clocking mck @(posedge PCLK);
    default input #1step output #1ns;
    output PADDR, PSEL, PENABLE, PWRITE, PWDATA;
    input  PRDATA, PREADY, PSLVERR;
  endclocking

  // Passive Monitor Clocking Block: Sample all signals without driving
  clocking mon_ck @(posedge PCLK);
    default input #1step;
    input PADDR, PSEL, PENABLE, PWRITE, PWDATA, PRDATA, PREADY, PSLVERR;
  endclocking

  modport MASTER (clocking mck, input PCLK, PRESETn);
  modport MONITOR (clocking mon_ck, input PCLK, PRESETn);
endinterface

UVM Architecture: Phasing, Factory, ConfigDB & Transaction Flow

The Complete UVM 1.2 Component Hierarchy

The Universal Verification Methodology (UVM) standardizes testbench construction across semiconductor companies worldwide. Below is the structural transaction pipeline from stimulus creation to verification closure:

Component Base Class Primary Architectural Role Key Methods / Ports
Sequence Item uvm_sequence_item Encapsulates pin-level transactions into high-level randomized packets. do_copy, do_compare, do_print, convert2string
Sequence uvm_sequence Defines procedural stimulus flow and transaction generation patterns. body(), `uvm_do, start_item, finish_item
Sequencer uvm_sequencer Arbitrates between concurrent sequences and connects to the driver. seq_item_export
Driver uvm_driver Consumes sequence items and translates them into physical pin signals. seq_item_port.get_next_item(req), item_done()
Monitor uvm_monitor Passively samples pin signals, reconstructs packets, and broadcasts. uvm_analysis_port #(T) ap
Scoreboard uvm_scoreboard Compares actual DUT outputs from monitor against reference model predictions. uvm_analysis_imp, uvm_tlm_analysis_fifo
Agent uvm_agent Encapsulates driver, monitor, and sequencer into a reusable protocol block. is_active == UVM_ACTIVE / UVM_PASSIVE

Test uvm_test Root of the verification component tree; configures environment and starts sequences. run_phase(), phase.raise_objection()

UVM Phasing & Objection Handling

UVM components execute through standardized phases. The non-time-consuming phases (`build_phase`, `connect_phase`, `end_of_elaboration`) execute in zero simulation time. The `run_phase` is a time-consuming task where clock edges and transactions occur.

The Golden Rule of UVM Objections
A simulation terminates automatically when the total count of active objections across all components drops to zero. Every `phase.raise_objection(this)` must have exactly one matching `phase.drop_objection(this)`! A dropped objection that fails to execute leaves an objection leak, causing the simulator to hang indefinitely until watchdog timeout.

UVM Testbench Development: Building Reusable Agents & Scoreboards

Complete Production UVM Driver & Monitor Implementation

Below is a complete, syntactically verified UVM 1.2 driver for an APB4 protocol, demonstrating correct virtual interface usage, clocking block synchronization, and non-blocking transaction fetching:

tb/apb_driver.sv (Production-Grade UVM Driver) 
class apb_driver extends uvm_driver #(apb_seq_item);
  `uvm_component_utils(apb_driver)

  virtual apb_if.MASTER vif;

  function new(string name = "apb_driver", uvm_component parent = null);
    super.new(name, parent);
  endfunction

  function void build_phase(uvm_phase phase);
    super.build_phase(phase);
    if (!uvm_config_db#(virtual apb_if.MASTER)::get(this, "", "vif", vif)) begin
      `uvm_fatal("NO_VIF", {"Virtual interface must be set for: ", get_full_name(), ".vif"})
    end
  endfunction

  task run_phase(uvm_phase phase);
    // Reset bus signals to idle
    vif.mck.PSEL    <= 1'b0;
    vif.mck.PENABLE <= 1'b0;
    vif.mck.PWRITE  <= 1'b0;
    vif.mck.PADDR   <= '0;
    vif.mck.PWDATA  <= '0;

    wait(vif.PRESETn === 1'b1);
    @(vif.mck);

    forever begin
      seq_item_port.get_next_item(req);
      drive_transfer(req);
      seq_item_port.item_done();
    end
  endtask

  task drive_transfer(apb_seq_item item);
    // APB Setup Phase: Assert PSEL, drive Address and Write Control
    @(vif.mck);
    vif.mck.PADDR   <= item.addr;
    vif.mck.PWRITE  <= item.write;
    vif.mck.PSEL    <= 1'b1;
    vif.mck.PENABLE <= 1'b0;
    if (item.write) vif.mck.PWDATA <= item.data;

    // APB Access Phase: Assert PENABLE
    @(vif.mck);
    vif.mck.PENABLE <= 1'b1;

    // Wait for Slave PREADY
    while (!vif.mck.PREADY) @(vif.mck);

    // Capture Read Data if Read Transfer
    if (!item.write) item.data = vif.mck.PRDATA;
    item.slverr = vif.mck.PSLVERR;

    // Return to Idle
    @(vif.mck);
    vif.mck.PSEL    <= 1'b0;
    vif.mck.PENABLE <= 1'b0;
  endtask
endclass

Constrained Random Verification: Solvers, Distributions & Soft Constraints

Advanced SystemVerilog Constraint Techniques

Constrained-Random Verification (CRV) allows engineers to specify the legal envelope of stimulus using mathematical constraints, letting the simulator's random solver generate millions of unexpected, corner-case input permutations.

Constraint Construct Syntax Example Engineering Purpose
inside addr inside {[32'h0:32'hFFF], [32'h4000:32'h4FFF]}; Restricts variables to discrete values or continuous ranges.
dist (Weighting) length dist {1 := 50, [2:16] :/ 40, 64 := 10}; := assigns weight to each value; :/ divides weight across the range.
Implication (->) is_burst -> (burst_len > 1); Conditional constraint: if antecedent is true, consequent is enforced.
solve ... before solve trans_type before payload_size; Guides the solver's variable elimination order to prevent distribution distortion.
soft Constraints constraint c_delay { soft delay == 0; } Default constraint that can be overridden inline using randomize() with {}.
tb/axi_packet.sv (Constrained Random Packet Class) 
class axi_packet extends uvm_sequence_item;
  typedef enum bit [1:0] {FIXED = 2'b00, INCR = 2'b01, WRAP = 2'b10} burst_e;
  typedef enum bit [2:0] {BYTE = 3'b000, HALF = 3'b001, WORD = 3'b010, QUAD = 3'b011} size_e;

  rand bit [31:0]  addr;
  rand bit [7:0]   len;
  rand size_e      size;
  rand burst_e     burst;
  rand bit [31:0]  data_payload[];

  // 1. Solve burst type before address to ensure wrap alignment
  constraint c_order { solve burst before addr; }

  // 2. Wrap burst length must be 2, 4, 8, or 16
  constraint c_wrap_len {
    if (burst == WRAP) {
      len inside {1, 3, 7, 15}; // AxLEN = burst_length - 1
    }
  }

  // 3. Address alignment for wrapping bursts
  constraint c_wrap_align {
    if (burst == WRAP) {
      (addr % (1 << size)) == 0;
    }
  }

  // 4. Payload size must match burst length
  constraint c_payload_size {
    data_payload.size() == (len + 1);
  }

  // 5. Soft default: prefer word-aligned transfers
  constraint c_default_size {
    soft size == WORD;
  }

  `uvm_object_utils_begin(axi_packet)
    `uvm_field_int(addr, UVM_ALL_ON)
    `uvm_field_int(len, UVM_ALL_ON)
    `uvm_field_enum(size_e, size, UVM_ALL_ON)
    `uvm_field_enum(burst_e, burst, UVM_ALL_ON)
    `uvm_field_array_int(data_payload, UVM_ALL_ON)
  `uvm_object_utils_end

  function new(string name = "axi_packet"); super.new(name); endfunction
endclass
Module 6 · Checkers & Properties

SystemVerilog Assertions: Concurrent Checks, Temporal Logic & Protocols

Immediate vs. Concurrent Assertions

SystemVerilog Assertions (SVA) provide mathematically rigorous runtime and formal checking embedded directly into interfaces and RTL:

  • Immediate Assertions (`assert (condition)`): Evaluated procedurally in the active region like an `if` statement. Subject to simulation glitching if inputs toggle mid-cycle.
  • Concurrent Assertions (`assert property (@(posedge clk) ...)`): Evaluated based on clock edges. Signals are sampled in the Preponed region and evaluated in the Observed region, completely free of simulation race conditions.
SVA Operator Syntax Meaning Common Engineering Trap
Overlapping Implication A |-> B If antecedent $A$ is true, consequent $B$ must hold in the same clock cycle. Using |-> when a 1-cycle pipeline delay was intended.
Non-Overlapping Implication A |=> B If antecedent $A$ is true, consequent $B$ must hold in the next clock cycle ($+1$). Equivalent to A |-> ##1 B.
Consecutive Repetition sig [*N] Signal must remain asserted continuously for $N$ consecutive cycles. Large ranges like [*1:1000] cause state-space explosion in formal tools.
Past Sampling $past(sig, N) Samples the value of signal $N$ clock cycles in the past. Undefined at time zero unless guarded by reset.
One-Hot Functions $onehot(sig) Returns true if exactly one bit in vector is active high. Use $onehot0 if all-zero state is also legally permitted.
tb/handshake_sva.sv (Ready/Valid Protocol Checker) 
module handshake_sva #(parameter WIDTH = 32) (
  input logic             clk,
  input logic             rst_n,
  input logic             valid,
  input logic             ready,
  input logic [WIDTH-1:0] data
);

  // Property 1: Stability Rule - Once VALID is asserted, VALID and DATA must remain
  // stable until READY is asserted by the receiver.
  property p_valid_stability;
    @(posedge clk) disable iff (!rst_n)
    (valid && !ready) |=> (valid && $stable(data));
  endproperty
  a_valid_stability: assert property(p_valid_stability)
    else $error("[SVA_ERR] VALID dropped or DATA mutated while waiting for READY!");

  // Property 2: No X/Z on Handshake Signals during Active Operation
  property p_no_unknown_handshake;
    @(posedge clk) disable iff (!rst_n)
    !$isunknown(valid) && (valid |-> !$isunknown(data));
  endproperty
  a_no_unknown_handshake: assert property(p_no_unknown_handshake)
    else $error("[SVA_ERR] X or Z state detected on VALID or DATA payload!");

  // Cover Property: Observe full handshake transfer
  c_handshake_transfer: cover property(
    @(posedge clk) disable iff (!rst_n)
    valid && ready
  );
endmodule
Module 7 · Metrics & Sign-Off

Functional Coverage Closure: Covergroups, Crosses & Hole Triage

Code Coverage vs. Functional Coverage: The Verification Reality

A common trap for junior engineers is conflating 100% line or toggle coverage with verification closure. Code coverage (line, branch, condition, FSM state/arc, toggle) measures only what RTL structures were activated during simulation; it provides zero insight into whether the design implements the specification correctly. A completely unverified mode or missing error-handling logic may achieve 100% code coverage simply because the lines that do exist were executed.

Functional coverage is user-defined and specification-driven. It answers: "Have all functional scenarios, corner-case combinations, protocol states, and boundary conditions outlined in the verification plan been triggered and observed?"

Metric Type Source of Truth EDA Tool Instrumentation Sign-Off Requirement
Line & Branch Coverage RTL source code VCS -cm line+cond+branch, Xcelium -coverage b:c:e 100% (or waivers formally reviewed with design leads)
Toggle Coverage Netlist / RTL ports and internal nets VCS -cm tgl, Questa coverage save -onexit >95% on primary I/O, internal control registers
FSM State & Transition Synthesizable state machine encodings Automated FSM extraction in EDA compiler 100% of reachable states and legal transitions
Functional Coverage Verification Plan (vPlan) derived from Spec SystemVerilog covergroup, coverpoint, cross 100% mandatory for tape-out sign-off
Assertion Coverage SVA cover property statements VCS -cm assert, Questa assert cover 100% of defined legal protocol sequences observed

SystemVerilog Covergroup Construction: Bins, Transitions & Crosses

Modern functional coverage models leverage explicit bins, wildcard bins, state transition bins, conditional sampling, and multidimensional crosses. Below is a production-grade covergroup for an AXI4 memory controller interface capturing burst lengths, address boundaries, and write response crosses.

axi4_coverage_subscriber.sv — Production UVM Coverage Subscriber 
class axi4_coverage_subscriber extends uvm_subscriber #(axi4_transaction);
  `uvm_component_utils(axi4_coverage_subscriber)

  axi4_transaction tr_queue[$];
  axi4_transaction cur_tr;

  // Covergroup definition with sampling argument
  covergroup axi4_cg with function sample(axi4_transaction tr);
    option.per_instance = 1;
    option.comment      = "AXI4 Protocol & Boundary Coverage Model";
    option.goal         = 100;

    // Coverpoint 1: Burst Lengths (AxLEN: 0=1 beat, 255=256 beats)
    cp_burst_len: coverpoint tr.len {
      bins single_beat       = {0};
      bins short_burst       = {[1:7]};
      bins medium_burst      = {[8:63]};
      bins max_burst_axi3    = {15};      // AXI3 legacy limit
      bins max_burst_axi4    = {255};     // AXI4 full limit
      bins unaligned_lengths = {[64:254]};
    }

    // Coverpoint 2: Burst Type (FIXED, INCR, WRAP)
    cp_burst_type: coverpoint tr.burst {
      bins fixed = {2'b00};
      bins incr  = {2'b01};
      bins wrap  = {2'b10};
      illegal_bins reserved = {2'b11};
    }

    // Coverpoint 3: 4KB Boundary Crossing Address Analysis
    // AXI spec strictly forbids bursts crossing 4KB page boundaries!
    cp_addr_alignment: coverpoint (tr.addr[11:0]) {
      bins page_start       = {12'h000};
      bins near_4k_page_end = {[12'hFE0:12'hFFF]};
      bins mid_page         = default;
    }

    // Coverpoint 4: Response Status (OKAY, EXOKAY, SLVERR, DECERR)
    cp_resp: coverpoint tr.resp {
      bins okay   = {2'b00};
      bins exokay = {2'b01};
      bins slverr = {2'b10};
      bins decerr = {2'b11};
    }

    // Coverpoint 5: Transition Bins (Back-to-back response transitions)
    cp_resp_transition: coverpoint tr.resp {
      bins okay_to_slverr = (2'b00 => 2'b10);
      bins slverr_to_okay = (2'b10 => 2'b00);
      bins decerr_recovery = (2'b11 => 2'b00);
    }

    // Cross Coverage: Burst Type X Burst Length
    cross_burst_type_len: cross cp_burst_type, cp_burst_len {
      // WRAP bursts must have length 2, 4, 8, or 16 according to ARM AXI Spec!
      ignore_bins illegal_wrap_len = binsof(cp_burst_type.wrap) &&
                                     !binsof(cp_burst_len) intersect {1, 3, 7, 15};
    }

    // Cross Coverage: Address Boundary X Burst Length
    cross_page_crossing: cross cp_addr_alignment, cp_burst_len;
  endgroup

  function new(string name, uvm_component parent);
    super.new(name, parent);
    axi4_cg = new();
  endfunction

  virtual function void write(axi4_transaction t);
    cur_tr = t;
    axi4_cg.sample(cur_tr);
  endfunction
endclass

Triage Workflow: Analyzing Coverage Holes with Claude Code

When EDA coverage reports (e.g., Synopsys VCS urgReport or Cadence imc) indicate 92% coverage with persistent unhit bins, engineers face a time-consuming debug cycle. Unhit bins typically stem from one of four root causes:

  1. Over-Constrained Testbench: Conflicting or overly rigid constraint blocks preventing random stimulus from ever generating the target values.
  2. Missing Test Sequences: No sequence written to trigger rare fault scenarios (e.g., ECC double-bit error injection, arbitration starvation under backpressure).
  3. Unreachable / Dead Code: Configuration parameter static binds (e.g., CACHE_ENABLED=0) rendering certain hardware states physically unreachable in this SoC variant (requires formal waiver).
  4. DUT Functional Bug: DUT state machine hangs or drops transactions before the coverage sampling point is reached.

Module 9 · Standard Interconnects

Protocol Verification: AMBA APB4, AXI4/AXI-Lite & Streaming Interfaces

AMBA Interconnect Landscape in Modern SoCs

Protocol verification represents over 50% of the verification IP (VIP) deployed on high-performance SoCs. Understanding the handshake rules, transfer phases, and concurrency semantics of ARM AMBA protocols is critical for building robust verification environments.

Protocol Architecture Max Throughput Key Verification Hazards
APB4 (Peripheral Bus) Non-pipelined, 2-phase (SETUP, ACCESS), single master, low power. 1 transfer per 2 clock cycles minimum. Master changing address during ACCESS phase before PREADY asserted; ignoring PSLVERR.
AHB5 (High-perf Bus) Pipelined address & data phases, burst transfers, single shared bus. 1 transfer per cycle sustained in burst. Pipelined address/data phase decoupling; wait states inserted by HREADYOUT; cancel on error response.
AXI4 (System Interconnect) 5 independent parallel channels (AW, W, B, AR, R), full duplex, burst-based. Multiple concurrent read/write transactions per clock. Out-of-order data interleaving across transaction IDs; deadlocks from circular VALID/READY dependencies; 4KB page crossing.
AXI4-Stream Point-to-point streaming data packet transfers, no address channel. Variable byte width line-rate streaming. Backpressure deadlock; TLAST dropped prematurely; byte strobe TKEEP / TSTRB mismatch.

AXI4 Two-Way Handshake Causality Rules: SVA Verification

The ARM AMBA AXI4 specification defines strict rules regarding dependency between VALID and READY signals to guarantee deadlock-free architectures:

  • Rule 1 (Master Independence): A transmitting master MUST NOT wait for the receiver to assert READY before asserting VALID. VALID must be asserted unconditionally once payload data is valid.
  • Rule 2 (Receiver Freedom): A receiving slave CAN wait for VALID before asserting READY, OR it may assert READY speculatively before VALID arrives.
  • Rule 3 (Stability Rule): Once a master asserts VALID, it MUST keep VALID high and retain the exact payload data until the handshake completes (VALID && READY).
axi4_channel_sva.sv — AXI Handshake Compliance Checker
module axi4_channel_sva #(parameter WIDTH = 64) (
  input logic             clk,
  input logic             rst_n,
  input logic             valid,
  input logic             ready,
  input logic [WIDTH-1:0] data
);

  // Property: Stability until acknowledged
  property p_handshake_stability;
    @(posedge clk) disable iff (!rst_n)
    (valid && !ready) |=> (valid && $stable(data));
  endproperty
  assert_handshake_stability: assert property(p_handshake_stability)
    else $error("[AXI_ERR_01] Master modified data or de-asserted VALID before READY was high!");

  // Property: No combinational loop (READY must not depend combinatorially on VALID in Master)
  // Verified formally in JasperGold or with strict timing assertions
  property p_valid_no_x;
    @(posedge clk) disable iff (!rst_n)
    !$isunknown(valid);
  endproperty
  assert_valid_no_x: assert property(p_valid_no_x)
    else $error("[AXI_ERR_02] VALID signal contains X or Z!");

  // Coverage: Measure handshake latency distribution
  cover_zero_wait: cover property(
    @(posedge clk) disable iff (!rst_n)
    valid && ready
  );

  cover_slave_backpressure: cover property(
    @(posedge clk) disable iff (!rst_n)

#!/usr/bin/env python3
"""
regression_cluster.py - ASIC Regression Log Analyzer & Failure Classifier
Usage: python regression_cluster.py --log-dir ./sim_results --out report.md
"""

import os
import re
import sys
import argparse
from collections import defaultdict

ERROR_PATTERNS = [
    re.compile(r"(UVM_FATAL\s+.*)", re.MULTILINE),
    re.compile(r"(UVM_ERROR\s+.*?:\s+\[(.*?)\]\s+(.*))", re.MULTILINE),
    re.compile(r"(\*E,ASSERT\s+.*)", re.MULTILINE),
    re.compile(r"(Assertion\s+`.*?'\s+failed.*)", re.MULTILINE),
    re.compile(r"(Segmentation fault.*)", re.MULTILINE),
    re.compile(r"(PH_TIMEOUT\s+.*)", re.MULTILINE)
]

SEED_PATTERN = re.compile(r"(?:-seed|\+ntb_random_seed=|\+seed=)\s*(\d+)", re.IGNORECASE)

def parse_log(filepath):
    """Scans a single simulation log file for errors and seed."""
    with open(filepath, 'r', errors='ignore') as f:
        content = f.read()

    seed = "Unknown"
    seed_match = SEED_PATTERN.search(content)
    if seed_match:
        seed = seed_match.group(1)

    # Check for passed status
    if "TEST PASSED" in content or "UVM_TEST_TOP: PASSED" in content:
        return "PASS", seed, None

    # Search for error signatures
    for pattern in ERROR_PATTERNS:
        match = pattern.search(content)
        if match:
            # Normalize error signature to remove variable time/memory addresses
            sig = match.group(0).strip()
            sig = re.sub(r"@\s*\d+\s*(?:ps|ns|fs)", "@ ", sig)
            sig = re.sub(r"0x[0-9a-fA-F]+", "0x", sig)
            return "FAIL", seed, sig

    if "UVM_ERROR" in content or "Fatal error" in content:
        return "FAIL", seed, "Unclassified Simulation Error"

    return "UNKNOWN", seed, None

def run_analysis(log_dir):
    clusters = defaultdict(list)
    pass_count = 0
    fail_count = 0
    unknown_count = 0

    for root, _, files in os.walk(log_dir):
        for file in files:
            if file.endswith((".log", ".rpt", ".txt")):
                path = os.path.join(root, file)
                status, seed, sig = parse_log(path)
                if status == "PASS":
                    pass_count += 1
                elif status == "FAIL":
                    fail_count += 1
                    clusters[sig].append((file, seed))
                else:
                    unknown_count += 1

    total = pass_count + fail_count + unknown_count
    pass_rate = (pass_count / total * 100) if total > 0 else 0.0

    print(f"[SUMMARY] Total: {total} | Pass: {pass_count} ({pass_rate:.1f}%) | Fail: {fail_count} | Unique Clusters: {len(clusters)}")
    return total, pass_count, fail_count, clusters

if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="ASIC Regression Analyzer")
    parser.add_argument("--log-dir", required=True, help="Directory containing log files")
    args = parser.parse_args()
    run_analysis(args.log_dir)

Formal Property Verification (FPV) vs. Dynamic Simulation & UPF Power-Aware DV

Formal Verification: Mathematical Proof vs. Monte Carlo Simulation

Dynamic simulation (SystemVerilog/UVM) is inherently incomplete: even a 100-million cycle regression samples only an infinitesimal fraction of an SoC's $2^{2000}$ possible state space. Formal Property Verification (FPV) leverages mathematical algorithms (SAT/SMT solvers, Bounded Model Checking, Craig Interpolation, k-induction) to prove that an assertion holds across all possible stimulus combinations for infinite cycles, or it returns a precise counterexample trace demonstrating the failure.

Dimension Dynamic Simulation (VCS / Xcelium) Formal Verification (VC Formal / JasperGold)
Stimulus Generation Testbench sequences, random seeds, constraints. Exhaustive mathematical solver searches all legal inputs.
Completeness Statistical confidence bounded by functional coverage. 100% mathematical proof within bounded/unbounded domain.
Corner Case Reachability Requires explicit random sequences or directed tests. Uncovers deep, obscure multi-cycle bugs in minutes.
Primary Failure Mode Simulation hang, objection leak, coverage deficit. State-space explosion (memory/time limit reached).
Optimal Use Cases End-to-end SoC data path, firmware boot, mixed-signal. Arbiters, FIFO controllers, credit bridges, protocol decoders, security firewalls.

Low-Power Power-Aware Simulation with IEEE 1801 (UPF 3.0)

Modern battery-powered SoCs feature dynamic voltage and frequency scaling (DVFS), power gating, multiple voltage domains, and retention flip-flops. Simulating pure RTL does not account for power state transitions—when a domain powers off, its outputs float to unknown states ('X'), corrupting always-on logic unless protected by isolation cells.

UPF (Unified Power Format) Simulation couples power architectural intent with SystemVerilog simulation:

  • Isolation Cells: Clamps powered-down domain outputs to safe logic '0' or '1' before reaching active domains.
  • Level Shifters: Translates signals traversing different voltage islands (e.g., 0.75V core logic to 1.8V I/O domain).
  • Retention Registers: Preserves state machine register contents during deep sleep using a secondary always-on backup rail.
  • Power State Table (PST): Defines legal operational modes (ACTIVE, SLEEP, DEEP_SLEEP, SHUTDOWN).

`timescale 1ns/1ps

// 1. APB Interface with Clocking Block
interface apb_if(input logic pclk);
  logic        preset_n;
  logic [31:0] paddr;
  logic        psel;
  logic        penable;
  logic        pwrite;
  logic [31:0] pwdata;
  logic [3:0]  pstrb;
  logic [31:0] prdata;
  logic        pready;
  logic        pslverr;

  // Master Clocking Block to eliminate race conditions
  clocking mck @(posedge pclk);
    default input #1step output #1ns;
    output paddr, psel, penable, pwrite, pwdata, pstrb;
    input  prdata, pready, pslverr;
  endclocking
endinterface

// 2. Transaction Class with Constraints
class apb_trans;
  rand bit [31:0] addr;
  rand bit [31:0] data;
  rand bit        write;
  rand bit [3:0]  strb;
  bit [31:0]      rdata;
  bit             slverr;

  constraint c_addr_aligned { addr[1:0] == 2'b00; }
  constraint c_addr_range   { addr < 32'h0000_1000; }
  constraint c_strb_valid   { strb inside {4'b1111, 4'b0011, 4'b1100, 4'b0001}; }
endclass

// 3. Scoreboard Class using Associative Memory Model
class apb_scoreboard;
  bit [31:0] mem[int];
  int match_count = 0;
  int error_count = 0;

  function void check_write(bit [31:0] addr, bit [31:0] data);
    mem[addr] = data;
    $display("[SB_WRITE] Stored Addr: 0x%08h | Data: 0x%08h", addr, data);
  endfunction

  function void check_read(bit [31:0] addr, bit [31:0] actual_data);
    if (!mem.exists(addr)) begin
      $display("[SB_WARN] Read from unwritten addr 0x%08h!", addr);
    end else if (mem[addr] === actual_data) begin
      match_count++;
      $display("[SB_PASS] Match @ 0x%08h: Exp=0x%08h, Act=0x%08h", addr, mem[addr], actual_data);
    end else begin
      error_count++;
      $error("[SB_FAIL] Mismatch @ 0x%08h: Exp=0x%08h, Act=0x%08h", addr, mem[addr], actual_data);
    end
  endfunction

  function void report();
    $display("========================================");
    $display("SCOREBOARD REPORT: Matches=%0d, Errors=%0d", match_count, error_count);
    $display("========================================");
  endfunction
endclass

// 4. Testbench Environment
program automatic apb_test(apb_if vif);
  apb_scoreboard sb = new();

  task automatic drive_write(apb_trans tr);
    @(vif.mck);
    vif.mck.psel    <= 1'b1;
    vif.mck.pwrite  <= 1'b1;
    vif.mck.paddr   <= tr.addr;
    vif.mck.pwdata  <= tr.data;
    vif.mck.pstrb   <= tr.strb;
    vif.mck.penable <= 1'b0;

    @(vif.mck);
    vif.mck.penable <= 1'b1;
    while (!vif.mck.pready) @(vif.mck);

    sb.check_write(tr.addr, tr.data);
    @(vif.mck);
    vif.mck.psel    <= 1'b0;
    vif.mck.penable <= 1'b0;
  endtask

  task automatic drive_read(apb_trans tr);
    @(vif.mck);
    vif.mck.psel    <= 1'b1;
    vif.mck.pwrite  <= 1'b0;
    vif.mck.paddr   <= tr.addr;
    vif.mck.penable <= 1'b0;

    @(vif.mck);
    vif.mck.penable <= 1'b1;
    while (!vif.mck.pready) @(vif.mck);

    tr.rdata = vif.mck.prdata;
    sb.check_read(tr.addr, tr.rdata);
    @(vif.mck);
    vif.mck.psel    <= 1'b0;
    vif.mck.penable <= 1'b0;
  endtask

  initial begin
    apb_trans tr = new();
    vif.preset_n <= 1'b0;
    repeat (5) @(vif.mck);
    vif.preset_n <= 1'b1;

    // Run 50 randomized write-read verification cycles
    for (int i = 0; i < 50; i++) begin
      assert(tr.randomize());
      drive_write(tr);
      drive_read(tr);
    end

    sb.report();
    $finish;
  end
endprogram

    end

      `uvm_error("SB_LEAK", $sformatf("Simulation ended with %0d unconsumed items left in FIFO queue!",

Write SVA Handshake Properties for Ready/Valid Interfaces

Objective: Formulate mathematical SystemVerilog Assertions (SVA) and functional cover properties for an AMBA/Streaming ready-valid channel. Ensure properties are compliant with both dynamic simulation (Synopsys VCS / Cadence Xcelium) and Formal Property Verification (Cadence JasperGold / Synopsys VC Formal).

ready_valid_sva.sv — Formal Property Verification Unit
module ready_valid_sva #(
  parameter WIDTH = 64,
  parameter MAX_WAIT = 16
)(
  input logic             clk,
  input logic             rst_n,
  input logic             valid,
  input logic             ready,
  input logic [WIDTH-1:0] data
);

  // Property 1: Stability Rule - Data and Valid cannot change while stalled
  property p_stability;
    @(posedge clk) disable iff (!rst_n)
    (valid && !ready) |=> (valid && $stable(data));
  endproperty
  assert_stability: assert property(p_stability)
    else $error("[SVA_STABILITY_FAIL] VALID dropped or DATA changed while waiting for READY!");

  // Property 2: Liveness Rule - Receiver must assert READY within MAX_WAIT cycles
  property p_liveness;
    @(posedge clk) disable iff (!rst_n)
    valid |=> ##[0:MAX_WAIT] ready;
  endproperty
  assert_liveness: assert property(p_liveness)
    else $error("[SVA_LIVENESS_FAIL] READY was not asserted within %0d cycles of VALID!", MAX_WAIT);

  // Property 3: No Unknowns (X/Z) on payload during transfer
  property p_no_x_on_valid;
    @(posedge clk) disable iff (!rst_n)
    valid |-> !$isunknown(data);
  endproperty
  assert_no_x: assert property(p_no_x_on_valid)
    else $error("[SVA_X_DETECTED] Payload contains unknown state (X/Z) while VALID is asserted!");

  // Property 4: Reset Deassertion - VALID must be 0 immediately upon reset
  property p_reset_state;
    @(posedge clk)
    !rst_n |-> (valid == 1'b0);
  endproperty
  assert_reset: assert property(p_reset_state)
    else $error("[SVA_RST_FAIL] VALID asserted during active reset!");

#!/usr/bin/env python3
"""
dv_log_triage.py - ASIC Regression Log Analyzer & Failure Clustering Engine
"""
import os
import re
import sys
import json
from collections import defaultdict

REGEX_PATTERNS = {
    "UVM_ERROR": re.compile(r"UVM_ERROR\s+(?:(?:\S+)\((\d+)\))?\s*:\s*(?:reporter|[\w\.]+)\s*\[(.*?)\]\s*(.*)"),
    "UVM_FATAL": re.compile(r"UVM_FATAL\s+(?:(?:\S+)\((\d+)\))?\s*:\s*(?:reporter|[\w\.]+)\s*\[(.*?)\]\s*(.*)"),
    "SVA_ASSERT": re.compile(r"\*E,ASSERT\s+\((\w+)\):\s+(.*)"),
    "SIM_CRASH": re.compile(r"(Segmentation fault|Internal compiler error|core dumped)"),
}
SEED_RE = re.compile(r"(?:-seed|\+ntb_random_seed=|\+seed=)\s*(\d+)")

def triage_log(filepath):
    with open(filepath, 'r', errors='ignore') as f:
        content = f.read()

    seed = "0"
    sm = SEED_RE.search(content)
    if sm:
        seed = sm.group(1)

    if "UVM_TEST_TOP: PASSED" in content or "TEST PASSED" in content:
        return "PASS", seed, None

    for err_type, pat in REGEX_PATTERNS.items():
        m = pat.search(content)
        if m:
            raw_sig = m.group(0).strip()
            # Normalize timestamps, pointers and random line numbers
            norm_sig = re.sub(r"@\s*\d+\s*(?:ps|ns)", "@ ", raw_sig)
            norm_sig = re.sub(r"0x[0-9a-fA-F]+", "0x", norm_sig)
            return "FAIL", seed, f"[{err_type}] {norm_sig[:120]}"

    return "FAIL", seed, "[UNKNOWN_FAIL] Simulation terminated without pass marker"

def main():
    if len(sys.argv) < 2:
        print("Usage: python dv_log_triage.py ")
        sys.exit(1)

    log_dir = sys.argv[1]
    clusters = defaultdict(list)
    passed, failed = 0, 0

    for root, _, files in os.walk(log_dir):
        for f in files:
            if f.endswith((".log", ".rpt", ".out")):
                path = os.path.join(root, f)
                status, seed, sig = triage_log(path)
                if status == "PASS":
                    passed += 1
                else:
                    failed += 1
                    clusters[sig].append({"file": f, "seed": seed})

    total = passed + failed
    pass_pct = (passed / total * 100) if total > 0 else 0.0

    print(f"# REGRESSION SUMMARY REPORT")
    print(f"- **Total Tests:** {total}")
    print(f"- **Passed:** {passed} ({pass_pct:.2f}%)")
    print(f"- **Failed:** {failed}")
    print(f"- **Unique Failure Clusters:** {len(clusters)}
")
    print("| Count | Error Signature | Example Reproduce Command |")
    print("|---|---|---|")
    for sig, runs in sorted(clusters.items(), key=lambda x: len(x[1]), reverse=True):
        cnt = len(runs)
        sample = runs[0]
        cmd = f"simv +ntb_random_seed={sample['seed']} -l debug.log"
        print(f"| **{cnt}** | `{sig}` | `{cmd}` |")

if __name__ == "__main__":
    main()

Production RTL & Testbench Sanitization Script

Before querying Claude with proprietary verification testbenches, engineering teams should execute an automated sanitization pre-processor. This script strips confidential project identifiers, hashes module names, and cleans internal comments:

sanitize_dv_code.py — Proprietary Code Anonymizer
#!/usr/bin/env python3
"""
sanitize_dv_code.py - Anonymizes proprietary ASIC IP and SystemVerilog code
"""
import re
import sys

# Replace proprietary codenames with generic engineering identifiers
SUBSTITUTIONS = [
    (r"project_titan", "soc_top"),
    (r"secure_vault_crypto", "security_engine"),
    (r"nvidia_\w+", "custom_ip"),
    (r"qualcomm_\w+", "custom_ip"),
    (r"0x[0-9a-fA-F]{8,}", "0x1000_0000"),  # Anonymize proprietary base addresses
]

def sanitize(code_text):
    # 1. Strip multi-line and single-line internal comments
    code_text = re.sub(r"/\*[\s\S]*?\*/", "", code_text)
    code_text = re.sub(r"//.*", "", code_text)

    # 2. Perform identifier replacements
    for pattern, replacement in SUBSTITUTIONS:
        code_text = re.sub(pattern, replacement, code_text, flags=re.IGNORECASE)

    # 3. Clean trailing whitespace
    lines = [line.rstrip() for line in code_text.splitlines() if line.strip()]
    return "
".join(lines)

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python sanitize_dv_code.py ")
        sys.exit(1)
    with open(sys.argv[1], 'r') as f:
        sanitized = sanitize(f.read())
    print(sanitized)

Can Claude directly simulate SystemVerilog or run UVM testbenches?

No. Claude is an LLM with no discrete-event simulation kernel, no constraint solver engine (such as those in Synopsys VCS, Cadence Xcelium, or Siemens Questa), and no waveform dump facility. Claude functions as an intelligent copilot that authors clean SystemVerilog/UVM components, generates SVA assertions, audits constraint distribution, and diagnoses simulation failure logs for execution by commercial simulators.

How does Claude help build modular UVM testbenches?

Claude constructs complete, structurally sound UVM 1.2 hierarchies: sequence items, drivers with virtual interface clocking block handshakes, monitors with analysis ports, sequencers, agents, scoreboards, and environment configurations. It enforces strict UVM factory registration and standard phasing rules.

Can Claude generate mathematically sound SystemVerilog Assertions (SVA)?

Yes. Claude translates English specifications and timing diagrams into concurrent assertions with explicit clocking, asynchronous reset disabling, temporal operators ($past, $rose, $fell, $stable), and proper implication operators (|-> vs |=>). It also provides corresponding cover properties to verify non-vacuous triggering.

How does Claude diagnose UVM simulation hangs and objection issues?

Claude analyzes simulation transcript logs and UVM component code to identify objection leaks (raise without matching drop), deadlocks in handshake loops where driver and DUT circular-wait, uninitialized virtual interfaces, and silent uvm_config_db lookup mismatches.

Can Claude analyze functional coverage reports and close coverage holes?

Yes. When provided with coverage summary reports (such as urgReport or coverage.rpt), Claude identifies un-exercised coverpoints, cross-product voids, and illegal state combinations. It recommends targeted constrained-random stimulus modifications or directed test sequences to achieve 100% coverage closure.

Is it safe to share proprietary ASIC testbenches, RTL, and verification plans with Claude?

Proprietary RTL source code, testbench verification IP, and microarchitectural specifications are confidential trade secrets. Engineering teams must never paste raw IP into public AI portals. How does Claude differentiate simulation, formal verification, and equivalence checking?

Simulation exercises a finite subset of temporal test vectors using dynamic event schedulers. Formal Property Verification (FPV) uses mathematical solvers to prove whether an assertion holds across all possible reachable states. Equivalence Checking (LEC) mathematically verifies that two structural netlists (e.g. RTL vs synthesized netlist) implement identical combinational Boolean logic.
