The CDC Reconvergence Problem

By EcrioniX • Sep 24, 2026 • 7 min read

You’ve learned to use a 2-flop synchronizer to safely pass a signal across clock domains. But what happens when you need to pass two related signals? If you send them through separate synchronizers, you've just triggered a catastrophic ASIC failure known as CDC Reconvergence.

1. The Flaw in Synchronizers: The 1-Cycle Uncertainty

To understand reconvergence, we first have to understand the fundamental limitation of a standard 2-flop synchronizer. A synchronizer prevents metastability by giving the flip-flop an entire clock cycle to resolve its voltage to a valid 0 or 1.

However, what a synchronizer cannot guarantee is exactly which clock cycle the signal will be captured on. Because the transmit (TX) clock and receive (RX) clock are asynchronous, the TX signal might arrive a picosecond before the RX clock edge, or a picosecond after it.

Because of tiny variations in physical wire routing and temperature, a signal arriving very close to the clock edge has a 1-cycle uncertainty. It might get captured on cycle N, or it might get captured on cycle N+1.

2. The Disaster: Reconverging Synchronizers

Imagine you have a state machine in the TX domain that outputs a 2-bit state: TX_A and TX_B. The state transitions from 00 directly to 11.

You need to read this state in the RX domain. Knowing that CDC is dangerous, you instantiate two separate 2-flop synchronizers: one for A and one for B. You then combine their outputs (RX_A and RX_B) into an AND gate in the RX domain.

The Phantom State

Both TX_A and TX_B flip from 0 to 1 at the exact same time. However, due to the 1-cycle uncertainty we discussed, the synchronizer for A captures the '1' on Clock Edge 1, but the synchronizer for B barely misses it and captures the '1' on Clock Edge 2.

For one entire clock cycle, the RX domain sees RX_A = 1 and RX_B = 0. Your logic briefly reads a state of 10. This is an illegal Phantom State that never actually existed in the TX domain. If your state machine acts on this 10, your entire chip crashes.

3. How to Fix CDC Reconvergence

To safely pass related signals across a clock domain boundary, you must guarantee that the destination domain never sees a partially updated state. There are three standard industry ways to do this.

Fix #1: Gray Encoding (For Counters & Pointers)

If the signals you are passing represent a counter (like a FIFO read/write pointer), you can convert the binary number into a Gray Code before crossing the domain.

In Gray Code, only one bit changes at a time. If the counter goes from 1 to 2, the Gray code goes from 01 to 11. Because only one wire flips, there is no risk of a multi-bit phantom state. The RX domain will either see the old value (01) or the new value (11). Both are perfectly valid.

Fix #2: Multi-Bit Consolidation (Data Valid Flag)

If you are passing a random payload of data (where multiple bits change at once), you cannot use Gray code. Instead, you use a coherency flag.

  1. Send the multi-bit data bus directly into the RX domain without any synchronizers.
  2. Wait for the data to settle physically.
  3. Send a single 1-bit Data_Valid flag through a 2-flop synchronizer into the RX domain.
  4. In the RX domain, only latch the data bus when the synchronized Data_Valid signal goes high.

Because only a single bit (the Valid flag) is being synchronized, there is no reconvergence problem. The multi-bit data is guaranteed to be perfectly stable before the RX domain is allowed to look at it.

Fix #3: Pre-CDC Logic Merging

If you are simply passing two flags (like Interrupt_A and Interrupt_B) to trigger a single event in the RX domain, do not cross them separately and AND them in the RX domain.

Instead, put the AND gate in the TX domain. Combine them into a single Merged_Interrupt flag, and pass that single flag through a synchronizer. Always reduce signals in the source domain before crossing when possible.

Key Takeaways

  • Never pass multiple related signals through separate synchronizers.
  • Synchronizers have a 1-cycle uncertainty; they will not output aligned signals at the same time.
  • Use Gray Code for counters (like Async FIFOs).
  • Use a synchronized "Valid" flag to safely capture multi-bit data buses.
