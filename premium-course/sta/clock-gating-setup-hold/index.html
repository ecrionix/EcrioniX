STA / Module 4: Advanced Clocking
Lesson 4.6

Clock Gating Setup/Hold Checks

Clock gating is the single most effective dynamic power reduction technique in digital design — and one of the easiest places to introduce a silent, catastrophic timing bug. The enable signal that turns a clock branch on or off is itself subject to a setup/hold check against the clock, and getting this wrong does not produce a slow chip. It produces a glitching clock and a broken one.

1. Why clock gating exists

A flip-flop that isn't being used this cycle (its enable is low, so it should hold its current value) still has its clock toggling every cycle if the clock tree is not gated. Every toggle burns dynamic power (P = C·V²·f) even though no useful work happens. In a modern SoC where clock trees can account for 30-50% of total dynamic power, gating unused clock branches is not optional — it is one of the largest levers available for meeting a power budget.

Rather than gating each flop's clock pin individually (which would create a combinational AND gate directly on the clock net — a glitch hazard, discussed below), designs use a purpose-built cell called an Integrated Clock Gating cell (ICG), typically built from a latch plus an AND gate, placed once per group of flops sharing an enable condition.

2. Inside an ICG: why the latch matters

A naive implementation would be gated_clk = clk AND enable using a plain combinational AND gate. This is dangerous: if enable changes anywhere except while clk is already low, the AND gate can produce a runt pulse — a partial, too-short clock edge — on the gated output. A runt pulse can partially clock a flop into a metastable or corrupted state without ever showing up as a "violation" in a naive check, because it isn't a full clock edge at all.

The standard ICG structure solves this with a level-sensitive latch in front of the AND gate:

module ICG ( input wire CLK, input wire EN, input wire TE, // test/scan enable, bypasses gating during scan shift output wire GCLK ); wire en_latched; // Latch is transparent while CLK is LOW, holds while CLK is HIGH latch_low_transparent u_lat ( .D(EN | TE), .G(~CLK), .Q(en_latched) ); assign GCLK = CLK & en_latched; endmodule

Because the latch only allows EN to change while CLK is already low, the AND gate only ever sees a stable, already-settled enable value by the time CLK rises — the enable can never change mid-high-phase and truncate an edge. This guarantees the gated clock output is always either a full, clean pulse or no pulse at all — never a runt.

3. The timing check: enable setup and hold relative to the clock

Even with the glitch-free latch structure, the enable signal EN is still combinational logic feeding into a timing-sensitive element (the latch), and it is checked exactly like a data pin on a flip-flop — with setup and hold requirements relative to the clock edge that closes the latch:

CheckRelative toWhat it guaranteesIf violated
ICG setupFalling edge of CLK (when the latch closes/becomes opaque)EN is stable and correctly reflects the desired gating decision before the latch captures itThe latch may capture a stale or transitioning EN value, gating the wrong cycle's clock — a flop that should have updated silently doesn't, or vice versa
ICG holdSame falling edgeEN does not change immediately after the latch closes in a way that races through parasitic pathsRare in practice given latch structure, but still checked for completeness in signoff
This is fundamentally a data-checking-against-a-clock-generator problem. STA does not treat the ICG output as a "free" derived clock — it is declared as a generated clock (see Lesson 4.7) with the ICG explicitly identified via set_clock_gating_check, and PrimeTime automatically inserts the enable setup/hold checks at every ICG instance without the engineer needing to write a manual timing arc for each one.
4. SDC: set_clock_gating_check
# Apply a uniform clock gating check margin design-wide set_clock_gating_check -setup 0.15 -hold 0.05 # Or override for a specific gating instance set_clock_gating_check -setup 0.20 -hold 0.08 [get_cells u_icg_core_domain]

These margins are typically derived from the ICG cell's own Liberty timing arcs (the cell vendor characterizes EN-to-CLK setup/hold just like any other sequential timing arc) plus an additional design-level margin the STA team layers on top for extra safety, since a clock gating failure corrupts an entire clock domain rather than a single data bit.

5. Why a clock gating violation is worse than an ordinary setup/hold miss

An ordinary data path setup violation corrupts one bit of data at one flop. A clock gating violation can corrupt the clock feeding an entire cluster of downstream flops — potentially hundreds or thousands of registers sharing that gated branch — because the failure mode isn't "wrong data," it is "wrong or missing clock edge." This is why clock gating checks are treated as first-class, mandatory sign-off checks in every serious methodology, not an optional extra pass, and why set_clock_gating_check margins are frequently set more conservatively than equivalent data-path margins.

6. Interaction with low-power verification (UPF)

In designs using power intent (UPF/CPF) for multiple voltage/power domains, ICGs are frequently combined with isolation and level-shifting logic at domain boundaries. STA's clock gating check remains a purely timing question (is EN stable before the latch closes), but a functionally correct low-power design also needs UPF-driven structural checks (does every gated clock domain have correct isolation cells) — these are complementary, not overlapping, verification steps, and both must pass before a low-power SoC can tape out.
