STA / Module 8: Timing Exceptions
Lesson 8.5

Multicycle Paths (Hold)

When you adjust a setup check using set_multicycle_path -setup, the STA engine automatically shifts the hold check as well. This is often the source of major hold timing violations if you don't correct it.

1

The Shifting Hold Edge

By definition, a hold check verifies that data launched from the *same* clock edge does not overwrite data being captured. The hold edge is always derived relative to the setup edge (default is 1 edge prior).

If you push the setup edge forward by 1 cycle (MCP setup 2), the hold edge ALSO shifts forward by 1 cycle. This means the destination flop will expect the data to be held for an entire clock cycle! This is incredibly difficult to meet physically without massive buffer chains, and usually not what you intend.

Fixing the Hold MCP
# Shift setup forward by 1 cycle
set_multicycle_path -setup 2 -from [get_cells launch_reg] -to [get_cells capture_reg]

# Pull hold back by 1 cycle (to its original location)
set_multicycle_path -hold 1 -from [get_cells launch_reg] -to [get_cells capture_reg]

Crucial Rule: If you use -setup N, you almost always must apply -hold N-1 on the same path.
