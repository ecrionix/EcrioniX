Lesson 3.5

Virtual Clocks

Sometimes you need to constrain I/O paths for a clock that doesn't actually exist on any port in your design. Enter the Virtual Clock.

1

What is a Virtual Clock?

A virtual clock is a clock defined in your SDC constraints that is not attached to any physical pin or port in your design block.

Virtual Clock Definition

A reference clock used purely to model the timing of external launch or capture flops that live outside the current block.

SDC Command: Creating a Virtual Clock
# Create a physical clock attached to port 'clk'
create_clock -name SYS_CLK -period 10.0 [get_ports clk]

# Create a virtual clock (note the lack of get_ports!)
create_clock -name VIRT_CLK_50M -period 20.0
2

When to use them

Virtual clocks are heavily used in block-level synthesis and STA:

  • I/O constraints for a different clock: If your input data comes from an external chip running at 50MHz, but your internal logic runs at 100MHz.
  • Pure combinational (In-to-Out) blocks: If your block has no clocks, you must constrain inputs/outputs relative to a virtual clock to give the tool a time reference.
  • Clock tree uncertainty modeling: Sometimes virtual clocks are created to model external clock jitter separately from the internal clock tree.

By default, STA tools assume all clocks (physical and virtual) with a common base multiple are synchronous. Use set_clock_groups to define asynchronous domains if the virtual clock is truly independent.

🎯 What to remember

  • Virtual clocks have no physical port attached.
  • They act as external reference anchors for I/O delays.
  • Define them simply by omitting the port target in `create_clock`.
