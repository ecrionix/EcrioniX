Lesson 1.7

Propagation Delay vs. Contamination Delay

Every logic gate has not one but two delay numbers hiding inside its Liberty timing arc: the longest time an output can take to respond to an input change, and the shortest. Conflating these two — or worse, only ever thinking about the first one — is the single most common conceptual gap that trips up engineers moving from RTL design into STA.

1. Two questions, two different answers

For any logic gate, there are two very different questions you can ask about its delay:

  • "What is the longest time this gate could possibly take to produce a valid, stable output after its input changes?" — this is propagation delay (tpd), sometimes called max delay.
  • "What is the shortest time this gate could possibly take before its output starts changing at all, even a little, after its input changes?" — this is contamination delay (tcd), sometimes called min delay.

These are not the same number, and the gap between them is not noise — it reflects genuine, physical variation in transistor switching speed across process corners, voltage, temperature, and even which specific input pin of a multi-input gate switched. A single gate might have tpd = 45ps at its slowest corner and tcd = 18ps at its fastest — nearly a 2.5x spread for the exact same physical cell instance.

2. Why the name "contamination"

The term comes from the idea that a signal is "contaminated" — no longer guaranteed to hold its old, valid value — the instant the gate begins transitioning, even before the new, correct output value has fully settled. Between tcd and tpd, the output is in an undefined, transitional zone: not reliably the old value, not yet reliably the new value. Any downstream logic that samples the signal during this window gets an unpredictable result.

3. Direct mapping to setup and hold

This is the concept's real payoff: propagation delay and contamination delay map exactly onto the two register-to-register timing checks covered in Lesson 2, and understanding why clarifies something that otherwise feels like an arbitrary STA rule:

STA checkUses which delay?Why
Setup checkPropagation delay (max, worst-case slow)Setup asks "will the data have definitely finished settling by the time the clock needs it?" — you must assume the absolute slowest possible path to guarantee the answer is yes in every real chip, not just the average one.
Hold checkContamination delay (min, worst-case fast)Hold asks "could the next data value possibly start arriving too early, before the old value was safely captured?" — you must assume the absolute fastest possible path, because that is the scenario where new data has the best chance of racing in prematurely.
This is exactly why STA runs setup analysis at the slow process/voltage/temperature corner and hold analysis at the fast corner (Lesson 3.1 on PVT corners) — it isn't an arbitrary convention, it is the direct consequence of setup needing tpd (which is largest at the slow corner) and hold needing tcd (which is smallest at the fast corner). Once you see propagation vs. contamination delay as the transistor-level root cause, the entire slow-corner-for-setup / fast-corner-for-hold convention stops being a rule to memorize and becomes an obvious consequence of physics.
4. Where these numbers come from in the Liberty model

Standard cell vendors characterize both numbers for every timing arc in every cell, across every PVT corner, storing them in the .lib file as separate max and min delay tables (usually indexed by input transition time and output load capacitance, forming a two-dimensional lookup table per arc — see Lesson 5 on Liberty timing arcs in depth):

cell (NAND2_X1) { pin (Y) { timing () { related_pin : "A"; timing_type : combinational; cell_rise (delay_template_7x7) { /* propagation delay table, max */ } cell_fall (delay_template_7x7) { /* propagation delay table, max */ } } timing () { related_pin : "A"; timing_type : combinational; when : "min_condition"; /* simplified illustration */ cell_rise (delay_template_7x7) { /* contamination delay table, min */ } cell_fall (delay_template_7x7) { /* contamination delay table, min */ } } } }

In practice, most flows don't rely on a single Liberty file containing both — they use entirely separate Liberty library files characterized at different corners (a "max" library at the slow/hot/low-voltage corner, a "min" library at the fast/cold/high-voltage corner), and STA reads both simultaneously during a combined setup+hold analysis run, exactly as covered in Lesson 3.1.

5. A worked micro-example

Consider a single inverter with tpd = 40ps (slow corner) and tcd = 15ps (fast corner) driving directly from a launch flop's Q pin to a capture flop's D pin, with zero additional logic in between (the tightest possible hold-risk scenario):

  • For setup: the tool assumes the inverter takes the full 40ps to guarantee the new data value has definitely arrived and settled before checking against the required time — using anything less would risk declaring a path "met" that could actually still be settling in real, slow-corner silicon.
  • For hold: the tool assumes the inverter could switch in as little as 15ps, checking whether that arrival time is still safely after the capture flop's hold window closes — using anything more (i.e., assuming the slow 40ps number for a hold check) would risk missing a real race condition that fast-corner silicon could actually hit.

This single inverter, with its two different delay numbers, is a miniature version of exactly why full-chip STA needs two separate, corner-consistent analysis runs rather than one "average" delay number applied everywhere.
