Lesson 9.4

Fixing Setup: Pipelining & Retiming

When the combinatorial cloud between two flops is inherently too long, you can't fix it with sizing. You must change the microarchitecture using pipelining or retiming.

1

Pipelining

Pipelining involves intentionally inserting a new flip-flop in the middle of a massive combinatorial logic path. This breaks the single long timing path into two shorter timing paths.

Latency vs Throughput

Pipelining increases the latency (it now takes 2 clock cycles instead of 1 to get the result), but it allows the clock frequency to be doubled, dramatically improving overall system throughput.

RTL Change Required: Pipelining fundamentally changes the cycle-by-cycle behavior of the design. You cannot do this automatically in an ECO. The RTL designer must update the code and verify the new timing against the protocol.

2

Retiming

What if Path A has negative slack (violating setup) but Path B (which immediately follows Path A) has plenty of positive slack? We can shift the boundary between them.

Retiming: Physically moving a flip-flop backward or forward through the combinatorial logic. If we move the flop backward, we reduce the logic depth of the preceding path (fixing its setup) and increase the logic depth of the following path (eating into its positive slack).

Advanced synthesis tools can perform retiming automatically, moving register boundaries without changing the overall cycle latency from input to output.
