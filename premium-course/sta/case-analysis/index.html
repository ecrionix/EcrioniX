Lesson 8.6

Case Analysis (set_case_analysis)

set_case_analysis forces a specific logical value (0 or 1) onto a net during static timing analysis. This is critical for mode-switching, like configuring the chip for test vs. functional mode.

1

Why Case Analysis?

Modern chips have multiplexed clocks. A single flop might receive a functional high-speed clock in normal operation, and a slow, externally driven clock during scan test (DFT). You cannot (and should not) analyze timing for both modes simultaneously, because they have entirely different constraints and clock definitions.

By applying a case analysis, you force the multiplexer select pin to a constant value, thereby shutting off one path entirely for the current STA run.

Isolating Functional Mode
# Force test_mode pin to 0. This disables all test clock paths through MUXes.
set_case_analysis 0 [get_ports test_mode_en]

When this is run, STA simply stops propagating signals through the '1' input of any multiplexer controlled by test_mode_en.
