Module 3, Lesson 2: Half-Cycle Paths (Negedge)

Introduction to Half-Cycle Paths

In standard synchronous design, data is launched on the rising edge (posedge) of a clock and captured on the subsequent rising edge of the same clock. This provides a full clock cycle (Tclk) for the signal to propagate through the combinational logic.

A half-cycle path occurs when data is launched on one clock edge (e.g., posedge) and captured on the very next opposite edge (e.g., negedge) of the same clock. This architectural decision fundamentally alters the setup and hold timing constraints of the path.

// Example: Inferring a Half-Cycle Path in Verilog module half_cycle_path ( input wire clk, input wire d_in, output reg d_out ); reg mid_reg; // Launch flop: triggered on positive edge always @(posedge clk) begin mid_reg <= d_in; end // Capture flop: triggered on negative edge always @(negedge clk) begin d_out <= mid_reg; end endmodule
Why use half-cycle paths?
  • DDR (Double Data Rate) Interfaces: To achieve higher throughput without increasing the clock frequency, data is transmitted on both the rising and falling edges.
  • Clock Centering / Source Synchronous IO: When clock and data are routed together, flipping the clock edge at the receiver is a common technique to center the capture edge inside the data eye.
  • Time Borrowing: If Path A is extremely fast and Path B is extremely slow, using a negedge flop in the middle gives Path A 0.5 cycles and Path B 1.5 cycles to evaluate.

The Setup Analysis Challenge

Because the capture edge occurs at Tclk / 2 rather than Tclk, the setup timing window is drastically reduced. The logic must evaluate twice as fast.

  • Launch Edge Time: 0 ns
  • Setup Capture Edge Time: Tclk / 2
  • Data Arrival Time: Tc2q + Tdata_path
  • Data Required Time: (Tclk / 2) - Tsetup
Setup Slack Formula:
Setup Slack = (Tclk / 2) - Tsetup - (Tc2q + Tdata_path)

Takeaway: Half-cycle paths make setup violations significantly more likely. You have exactly half the time to perform the same amount of logic computation.
The Hold Analysis Silver Lining

While setup becomes significantly harder to meet, hold time becomes incredibly easy. Why? Because of how STA tools strictly define a hold check.

By default, STA tools perform a hold check exactly one capture clock cycle prior to the setup capture edge.

  • Setup Capture Edge: Tclk / 2
  • Hold Capture Edge: (Tclk / 2) - Tclk = -Tclk / 2

This means the tool checks that the data launched at T = 0 does not race ahead and get incorrectly captured by the capture edge at -Tclk / 2. Because T = 0 is obviously after -Tclk / 2, the data naturally has an massive buffer of half a clock cycle.

Hold Slack Formula:
Hold Required Time = -Tclk / 2 + Thold
Hold Slack = Data Arrival - Hold Required Time
Hold Slack = (Tc2q + Tdata_path) - (-Tclk / 2 + Thold)
Hold Slack = Tc2q + Tdata_path + (Tclk / 2) - Thold

Takeaway: A half-cycle path fundamentally relaxes the hold constraint by Tclk / 2. It is exceedingly rare to see a hold violation on a true half-cycle path.
