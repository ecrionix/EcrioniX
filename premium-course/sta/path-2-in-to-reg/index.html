Lesson 3.2

Path 2: In-to-Reg (Input delays)

When data enters your chip from the outside world, the tool has no idea when it was launched. To time an In-to-Reg path, we must model the delay happening outside our design boundary.

1

The Challenge of In-to-Reg

An In-to-Reg path starts at an input port of your design and ends at the data pin of a capturing flip-flop inside your design.

  • Startpoint: Top-level input port.
  • Endpoint: Data input pin (D) of the first internal flip-flop.
Delivery Analogy

If you promise a customer a package by 5 PM (the clock edge), but you receive the raw materials from a vendor at 3 PM (the input delay), you only have 2 hours to process it. The synthesis tool needs to know about that 3 PM arrival time to optimize your logic.

2

Modeling with set_input_delay

To constrain this path, we tell the STA tool how much time was consumed outside the block relative to the clock. This shrinks the available time for your internal logic.

SDC Command
# The external delay is 2ns. If clock period is 10ns, internal logic has 8ns left.
set_input_delay -clock CLK -max 2.0 [get_ports data_in]

Warning: A common mistake is thinking set_input_delay sets how much time you have. It actually sets how much time is already gone before the data hits your input port.

🎯 What to remember

  • In-to-Reg paths capture external data into internal flops.
  • They start at input ports and end at internal flop D-pins.
  • You must constrain them using set_input_delay so the tool knows when data arrives.
