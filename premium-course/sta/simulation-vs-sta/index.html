STA / Module 2: STA Concepts & Terminology
Lesson 2.1

Simulation vs. Static Timing Analysis

Why isn't logic simulation enough to guarantee your chip works? Dynamic simulation verifies functionality but is blind to comprehensive timing closure. Static Timing Analysis (STA) guarantees timing without simulating a single test vector.

1

The Trap of Dynamic Simulation

Dynamic logic simulation (like running tests in ModelSim/VCS) applies test vectors (0s and 1s) to the inputs of your design and checks the outputs. While great for verifying RTL logic, it is fundamentally flawed for verifying timing.

⏳

Incomplete Coverage

You can only test the paths your stimulus explicitly exercises. A modern SoC has billions of timing paths. You cannot write vectors to toggle them all.

🐢

Too Slow

Simulating every possible transition combination across PVT (Process, Voltage, Temperature) corners would take hundreds of years.

2

What is Static Timing Analysis?

Static Timing Analysis (STA) is a mathematical approach to timing verification. It breaks the entire design into a timing graph and calculates the worst-case delays along every possible path, regardless of logical functionality.

Core Principle of STA

STA is exhaustive and vector-less. It proves that under all possible conditions, the data will always arrive at the flip-flop within the required setup and hold windows.

FeatureDynamic SimulationStatic Timing Analysis (STA)
MethodApplies vectors (0s, 1s) to inputsAnalyzes delay mathematically via graph traversal
CoverageOnly simulated paths100% of all timing paths exhaustively
SpeedSlow (scales with test length)Fast (scales with design size)
False PathsNaturally ignored (logic is real)Must be manually specified (tool assumes all paths can toggle)
3

The Downside of STA (Pessimism)

Because STA does not look at the actual logic vectors, it assumes that a signal can travel down ANY physical path, even if logically impossible.

⚠ False Paths

STA will report a timing violation on a path that can physically never happen logically (e.g., a path gated by a static config register). Engineers must write SDC constraints (set_false_path) to tell the tool to ignore these.

🎯 What to remember

  • Dynamic simulation is for functional verification.
  • STA is for timing verification.
  • STA is exhaustive, fast, and does not need test vectors.
  • Because STA is logic-blind, you must constrain out "False Paths".
