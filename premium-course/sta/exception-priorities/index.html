STA / Module 8: Timing Exceptions
Lesson 8.10

Exception Priorities and Conflicts

In a large SoC, you will have thousands of constraints loaded from different IP teams. What happens when constraints overlap or conflict?

1

The Priority Rule

STA tools resolve conflicting timing exceptions based on two main factors: the type of exception and the specificity of the path.

Generally, the priority from highest to lowest is:

  1. set_false_path
  2. set_max_delay / set_min_delay
  3. set_multicycle_path

If you declare a path as a multicycle path (MCP) and also as a false path, the tool will treat it as a false path and ignore the MCP.

2

Specificity Rule

If you have two of the *same* exception type, the more specific one wins. For example, a constraint targeting a specific cell instance will override a wildcard constraint that covers the entire clock domain.

Specificity Example
# Less specific: All paths from regA* are MCP 2
set_multicycle_path 2 -setup -from [get_cells regA*]

# More specific: Path from regA_fast to regB is MCP 1 (single cycle)
set_multicycle_path 1 -setup -from [get_cells regA_fast] -to [get_cells regB]

🎯 Key Takeaways for Module 8

  • Use set_false_path for CDCs and static registers.
  • Always adjust -hold when setting a -setup multicycle path.
  • Use set_case_analysis to cleanly separate functional vs. test timing modes.
  • When constraints overlap, false paths win, and specific pins beat wildcards.
