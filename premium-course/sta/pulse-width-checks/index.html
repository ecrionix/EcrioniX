Lesson 4.9

Pulse Width Checks

Setup and hold get all the attention, but there is a fifth, quieter timing check that fails a design just as fatally: pulse width. Every clock pin, and every level-sensitive control pin, has a minimum amount of time it must stay high (or low) for the internal circuitry to function — and a clock that toggles correctly in frequency but too briefly in each phase will corrupt data with zero warning from a frequency-only analysis.

1. Why a minimum pulse width exists at all

Inside a flip-flop or latch, the clock signal drives internal transmission gates and cross-coupled inverter pairs that need a certain minimum amount of time to fully complete their internal state transition once triggered. If the clock returns to its opposite level before this internal transition finishes, the cell can be left in an indeterminate or corrupted internal state — not a wrong logic value exactly, but a genuinely broken latch that may fail unpredictably on the next several cycles. This is a transistor-level, physical constraint of the cell itself, characterized once by the standard cell library vendor and reported in the Liberty (.lib) file as min_pulse_width timing arcs.

Pulse width checks are not unique to clocks — any level-sensitive control input with internal state-holding behavior (an asynchronous set/reset pin, a scan enable, a latch's own gate input) can have its own minimum pulse width requirement in the Liberty model.

2. Two flavors: minimum pulse width high and minimum pulse width low
CheckWhat it verifiesTypical dominant cause of violation
Min pulse width HIGHThe clock (or control signal) stays above its logic threshold for at least the cell's minimum required time before falling againClock gating enable toggling too close to a rising edge, truncating the high phase (see Lesson 4.6); duty-cycle distortion from asymmetric buffers
Min pulse width LOWThe clock stays below its logic threshold for at least the minimum required time before rising againSame causes as above, mirrored — a runt low phase from a mistimed gating disable, or aggressive duty-cycle-adjustment circuits pushed too far
3. Why frequency-only analysis misses this entirely

A clock can have a perfectly correct average frequency and still violate pulse width — imagine a 1GHz clock (1ns period) whose duty cycle has drifted to 5%/95% instead of 50/50 due to a buffer imbalance or a clock-gating glitch. The period is exactly right, so any check that only looks at edge-to-edge period spacing sees nothing wrong. But the 50ps high phase might be shorter than the flop's minimum pulse-width-high requirement (commonly 60-120ps in modern nodes), causing internal flop corruption on every single cycle despite the clock "looking correct" on a frequency counter or eye diagram at the period level.

This is exactly why pulse width is checked as its own, separate STA analysis — report_timing -delay_type min_pulse_width (or the tool-specific equivalent) walks every clock and control pin independently of the setup/hold register-to-register path analysis, comparing actual high/low durations against the Liberty-characterized minimum for that specific cell instance.
4. SDC: overriding or adding margin to pulse width checks
# Library-provided min_pulse_width is used automatically by default. # Override only when you have a specific reason (e.g. extra margin # for a known-noisy clock branch, or a custom cell without full # Liberty characterization): set_min_pulse_width -high 0.12 [get_clocks CLK_CORE] set_min_pulse_width -low 0.10 [get_clocks CLK_CORE]

Most designs never need to touch this command — the Liberty library's own characterized min_pulse_width arc is used automatically for every timing arc on every cell. set_min_pulse_width exists mainly for adding conservative design-level margin on top of the library number, not for replacing legitimate silicon characterization data with a guess.

5. Common real-world causes of pulse width violations
  • Clock gating enable racing the clock edge — if the ICG's enable signal (Lesson 4.6) changes too close to the boundary the latch is supposed to protect, the resulting gated pulse can be truncated even though the ICG structure itself is glitch-free in the binary sense (no runt below the latch's own protection) — the surviving pulse can still simply be too short if the enable timing is marginal.
  • Duty-cycle correction circuits pushed too aggressively — some designs intentionally adjust clock duty cycle (for DDR interfaces needing precise 50/50 clocks, for example) and an over-aggressive correction can overshoot, shrinking one phase below the minimum.
  • Multiplexed clock switching transients — during a live clock source switch (Lesson 4.8), a poorly designed glitch-free mux can still produce one abnormally short pulse right at the transition boundary even if it successfully avoids a full runt pulse.
  • OCV/derating on very short target pulses — a pulse width that is nominally fine but very close to the library minimum can be pushed into violation once on-chip variation derating (Lesson 3.2) is applied, exactly as with any other timing check.
6. Pulse width in the wider signoff picture

Pulse width, recovery, and removal (Lesson 2) are collectively the "other three" of STA's five fundamental checks that get far less classroom attention than setup and hold but are equally mandatory for signoff — PrimeTime's report_timing_summary reports WNS/TNS separately for each check type, and a clean setup/hold report with a hidden pulse-width failure is still a non-functional chip. A complete STA signoff always verifies all five checks, not just the two everyone remembers.
