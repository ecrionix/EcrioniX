STA / Module 8: Timing Exceptions
Lesson 8.2

False Paths (set_false_path)

A set_false_path exception explicitly tells the STA tool that a particular path is not required to meet any timing constraint. The tool will completely stop calculating setup and hold violations for it.

1

When to use False Paths?

  • Cross-Clock Domain (CDC) Paths: When signals cross between two asynchronous clock domains, data transitions are inherently unpredictable relative to the destination clock edge. We use synchronizers to safely capture this data. The raw timing path between the domains must be declared false.
  • Static or Quasi-Static Signals: Configuration registers (CSRs) that are programmed once at boot time and never change during active operation do not have strict single-cycle timing requirements.
  • Logically Unsensitizable Paths: Paths in the combinational logic that structurally exist but logically can never be activated due to boolean masking. (More on this in the next lesson).
example.sdc
# False path between asynchronous clocks
set_false_path -from [get_clocks clk_a] -to [get_clocks clk_b]

# False path from a static configuration register
set_false_path -from [get_cells cfg_mode_reg*]
