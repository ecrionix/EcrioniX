Lesson 3.4

Path 4: In-to-Out (Combinational feedthrough)

The rarest and most dangerous path is pure combinational logic from an input directly to an output. The In-to-Out path has no sequential elements to boundary the timing.

1

Combinational Feedthrough

An In-to-Out path starts at an input port and goes straight through combinational logic to an output port, without hitting a flip-flop clock pin or data pin.

  • Startpoint: Top-level input port.
  • Endpoint: Top-level output port.

Anti-pattern: Avoid feedthrough paths in block-level RTL. They make top-level timing closure a nightmare because delays aggregate across block boundaries uncontrollably. Always register your inputs or outputs (preferably both).

2

Constraining the Unbound Path

Because there is no clock inside the block for this path, how does STA know how to time it?

It relies entirely on the combination of set_input_delay and set_output_delay relative to a Virtual Clock.

SDC Command
# Virtual clock defined elsewhere...
set_input_delay -clock V_CLK 3.0 [get_ports feed_in]
set_output_delay -clock V_CLK 4.0 [get_ports feed_out]
# If V_CLK is 10ns, this block only gets 10 - 3 - 4 = 3ns for internal logic.

By constraining both the input arrival and output required time against the same clock, you create a bounded mathematical equation for the combinational delay.

🎯 What to remember

  • In-to-Out paths have no internal flops.
  • They are frowned upon in modern SoC design.
  • Constrained using both input and output delays against a common clock.
