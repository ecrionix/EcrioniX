STA / Module 5: Setup & Hold Math
Lesson 5.5

Common Clock Path Pessimism Removal (CPPR/CRPR)

In STA, tools analyze max delay for the launch path and min delay for the capture path to be conservative. But what if they share the same physical clock buffers?

1

The Artificial Pessimism

Consider a clock tree. The clock goes through a root buffer, then branches out to Flop A (launch) and Flop B (capture).

When doing a setup check, STA will assume the root buffer has maximum delay for the launch path (delaying data) and minimum delay for the capture path (making the clock arrive early).

A physical logic gate cannot have two different delays at the exact same moment in time! This introduces artificial pessimism.

2

CPPR to the Rescue

Clock Path Pessimism Removal (or Clock Reconvergence Pessimism Removal) calculates the delay difference artificially injected on the shared portion of the clock tree and adds it back to the slack.

CPPR Credit

CPPR = Max Delay of Common Path - Min Delay of Common Path

This "credit" is added to your slack, making it less negative. CPPR is essential for accurate timing sign-off.

🎯 What to remember

  • Tools are overly pessimistic by assuming shared buffers can be both fast and slow simultaneously.
  • CPPR calculates this error on the common clock path and removes it.
  • Always ensure CPPR is enabled during sign-off.
