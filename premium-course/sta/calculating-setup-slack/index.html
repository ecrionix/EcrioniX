Calculating Setup Slack

Module 2, Lesson 2 | EcrioniX STA Premium Course

1. The Setup Timing Equation

In synchronous digital design, a setup timing check ensures that data launched by a flip-flop has enough time to propagate through combinational logic and stabilize at the input of the receiving flip-flop before the next clock edge arrives.

For a design to function reliably, the following fundamental condition must be met:

Tclk ≥ Tcq + Tcomb_max + Tsetup

Where:

  • Tclk: The clock period (time between the launch edge and capture edge).
  • Tcq: The Clock-to-Q delay of the launching flip-flop.
  • Tcomb_max: The maximum combinational logic delay between the launch and capture flip-flops.
  • Tsetup: The setup time requirement of the capturing flip-flop (the time data must be stable before the clock edge).

If this equation holds true, the data will be safely captured. If not, the circuit will fail to meet timing, risking metastability or capturing incorrect data.

2. Data Arrival Time (DAT) vs Data Required Time (DRT)

Static Timing Analysis engines formalize the setup equation using two distinct concepts: Data Arrival Time (DAT) and Data Required Time (DRT).

Data Arrival Time (DAT)

DAT represents the actual time it takes for data to travel from the clock source, through the launch flip-flop, through the combinational logic, and arrive at the D-pin of the capture flip-flop.

DAT = Launch_Clock_Edge + Tclk_network_launch + Tcq + Tcomb_max

Data Required Time (DRT)

DRT represents the latest possible time the data must arrive at the capture flip-flop to be safely sampled. Because of the setup time requirement (Tsetup), the data must arrive before the capture clock edge.

DRT = Capture_Clock_Edge + Tclk_network_capture - Tsetup
3. Slack = DRT - DAT

To determine if a timing path passes or fails, the STA tool calculates the Slack. Slack is simply the difference between when the data is required and when it actually arrives.

Slack = Data Required Time (DRT) - Data Arrival Time (DAT)

The sign of the slack value tells us the health of the timing path:

  • Positive Slack (Slack > 0): The path meets timing. Data arrives before it is required. This is the goal.
  • Zero Slack (Slack = 0): The path barely meets timing. Data arrives exactly when required.
  • Negative Slack (Slack < 0): The path fails timing. Data arrives after it is required.
4. What Negative Setup Slack Means

When an STA report shows a negative setup slack, it means you have a Setup Violation (Max Delay Violation).

The Physical Consequence of Negative Slack
If a path has negative setup slack, the data is still transitioning (or hasn't arrived yet) while the capture flip-flop is trying to sample it. This can lead to metastability—the flip-flop's output gets stuck halfway between 0 and 1, eventually resolving randomly. This causes functional failure of the entire chip.

How do we fix negative setup slack? By revisiting our equation (Tclk ≥ Tcq + Tcomb_max + Tsetup), we have a few options:

  • Increase Tclk: Lower the clock frequency (often not acceptable for performance).
  • Reduce Tcomb_max: Optimize the combinational logic (pipelining, logic restructuring, sizing up gates).
  • Change Clock Routing: Adjust clock skew to push the capture edge out further (useful jitter/skew tuning).
5. Worked Example

Let's look at a practical example with real numbers. Assume ideal clocks (no clock network delay/skew).

Parameter Value
Clock Period (Tclk) 10.0 ns
Flip-Flop Clock-to-Q Delay (Tcq) 1.2 ns
Combinational Logic Max Delay (Tcomb_max) 7.5 ns
Flip-Flop Setup Time (Tsetup) 0.8 ns

Step 1: Calculate Data Arrival Time (DAT)

The launch edge occurs at 0.0 ns.

DAT = Launch_Edge + T_cq + T_comb_max DAT = 0.0 ns + 1.2 ns + 7.5 ns DAT = 8.7 ns

Step 2: Calculate Data Required Time (DRT)

The next capture edge occurs at 10.0 ns (one clock period later).

DRT = Capture_Edge - T_setup DRT = 10.0 ns - 0.8 ns DRT = 9.2 ns

Step 3: Calculate Slack

Slack = DRT - DAT Slack = 9.2 ns - 8.7 ns Slack = +0.5 ns

Conclusion: The slack is +0.5 ns. Because it is positive, this path easily meets timing! The data arrives 0.5 ns before the absolute deadline.

What if the logic was slower?

Imagine a designer adds more logic to the path, increasing Tcomb_max to 8.5 ns.

  • New DAT = 0.0 + 1.2 + 8.5 = 9.7 ns
  • DRT remains 9.2 ns
  • New Slack = DRT - DAT = 9.2 - 9.7 = -0.5 ns

The path now has negative slack. This is a setup violation, and the design will fail at this frequency.
