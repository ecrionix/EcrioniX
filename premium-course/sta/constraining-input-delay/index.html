Lesson 3.6

Constraining I/O paths (set_input_delay)

The command set_input_delay is arguably the most misunderstood SDC command. Let's break down exactly what it means and how to calculate it.

1

The Math Behind Input Delay

Input delay is the amount of time consumed by the upstream launch logic and routing before the signal reaches your block's boundary.

Formula

Input Delay = (Clock-to-Q of Launch Flop) + (External Combinational Delay) + (External Routing Delay)

If your clock period is `T`, the time left for your internal logic is:
Time_Available = T - Input_Delay - Internal_Setup

2

Max vs Min Delays

Real-world paths have variance. You must specify both the worst-case (max) and best-case (min) input delays for robust STA.

  • -max is used for Setup analysis (longest path).
  • -min is used for Hold analysis (shortest path).
SDC Command
# The external logic takes anywhere from 0.5ns (fastest) to 2.5ns (slowest)
set_input_delay -clock SYS_CLK -max 2.5 [get_ports data_in]
set_input_delay -clock SYS_CLK -min 0.5 [get_ports data_in]

Hold Violations at Ports: If you do not specify a `-min` value, the tool might assume 0ns. This can cause false hold violations or mask real ones at the input boundary.

🎯 What to remember

  • `set_input_delay` models time already spent outside your design.
  • Use `-max` for setup checks and `-min` for hold checks.
  • Calculate it as: external clk-to-Q + external combo delay.
