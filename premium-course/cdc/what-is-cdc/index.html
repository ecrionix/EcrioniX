CDC Course / Module 1: Introduction to CDC
Lesson 1.1

What is Clock Domain Crossing?

Q What is a "clock domain"?
A A group of digital logic that is all driven by the same clock signal. Every flip-flop inside that group toggles in sync with that one clock.
Q What is Clock Domain Crossing (CDC)?
A It's what happens when a signal travels from logic in one clock domain into logic in a different clock domain — meaning the source and destination don't share the same clock.
Q Why do chips even have multiple clock domains?
A
  • Different blocks need different speeds — a CPU core runs fast, a UART runs slow.
  • Some interfaces (PCIe, USB, Ethernet) have their own protocol-defined clock rate.
  • Clocks often come from separate oscillators/PLLs with no fixed phase relationship to each other.
Q What's the actual problem CDC causes?
A The receiving flip-flop can sample the incoming signal at the exact instant it's changing. Since the two clocks aren't synchronized, this can happen at any time — and it drives the flop into an unpredictable "metastable" state where its output is temporarily invalid.
Q Does the signal's speed matter?
A No. Even one single bit changing state, crossing between two independently-clocked domains, needs proper synchronization. The issue isn't speed — it's the lack of a fixed timing relationship between the two clocks.
Q What happens if CDC isn't handled correctly?
A
  • Intermittent, hard-to-reproduce bugs — not consistent failures.
  • Data corruption or system hangs that appear randomly.
  • Chips that pass simulation and lab testing, then fail unpredictably in the field.
Q How common is CDC in real chips?
A Extremely common — almost every modern SoC has multiple clock domains (CPU, memory, peripherals, PCIe, USB, etc.), so identifying and correctly synchronizing every CDC path is a standard, required part of chip design.

🎯 Key Takeaway

  • CDC = a signal crossing between two clock domains with no fixed timing relationship.
  • The risk is metastability — an unpredictable, invalid output state on the receiving flop.
  • Unhandled CDC causes silent, intermittent silicon bugs — not clean failures.
  • Every multi-clock chip needs proper CDC synchronization — it's not optional.
