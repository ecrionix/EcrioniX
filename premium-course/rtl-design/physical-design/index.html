Lesson 1.8

Physical Design (PD) — floorplan, place, route, timing overview

After synthesis, the design becomes geometry. Physical design places cells and routes wires on metal layers so the chip meets timing, power, and density rules. RTL authors who understand PD write friendlier RTL.

1

The PD playlist (simplified)

Physical design turns a netlist into geometry — wires have delay and congestion.

clk : ‾|_|‾|_|‾|_|‾|_ data : ====X========X==== (must be stable before edge) ^setup window capture edge --| hold: data must NOT change too soon after the edge
  1. Floorplan — die size, macro placement, IO rings, power grid sketch.
  2. Placement — standard cells find homes.
  3. Clock tree synthesis (CTS) — build a balanced clock network.
  4. Routing — connect pins with metal wires.
  5. Optimization / timing closure — iterate until paths meet constraints.

2

Why wires matter

In advanced nodes, wire delay and congestion can dominate. A “perfect” RTL path can fail because two blocks were placed far apart.

Architecture + hierarchy influence PD. Giant flat modules are harder to floorplan than clean hierarchies.

Wire delay intuition

Gate delay was king at old nodes. Today, a signal may spend more time traveling on metal than switching a transistor. Long unregistered paths crossing the die are timing killers.

⚠ Trap

“It met timing in synthesis” — pre-layout estimates omit real wire RC. Post-route STA is the truth for ASIC.

Congestion

Too many wires in one region → router cannot finish → PD asks for RTL pipelining or floorplan change. Symptoms: high utilization + timing fail on unrelated paths.

3

What RTL can do to help PD

  • Register outputs of large blocks (pipeline pressure valves)
  • Avoid needless wide buses crossing the whole chip
  • Keep clock domains intentional and documented
  • Don’t create 50-level combo clouds “because it simulated”

You are not expected to run Innovus/ICC2 in this course. You are expected to stop writing RTL that fights physics.

RTL habit that helps PD: register block outputs so long combo paths do not span the die.

registered_out.v
// Friendly for timing closure: register outputs of a block
module block_out_reg (
  input  wire       clk,
  input  wire       rst_n,
  input  wire [31:0] combo_result, // from heavy internal logic
  output reg  [31:0] block_q
);
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) block_q <= 32'd0;
    else        block_q <= combo_result;
  end
endmodule

// Why: PD can place this flop as a timing "pressure valve"
// between distant regions of the chip.

Pipelining example — 2-stage adder path

pipelined_add.v
module pipelined_add (
  input  wire        clk, rst_n,
  input  wire [31:0] a, b,
  output wire [32:0] sum
);
  reg [31:0] a_r, b_r;
  reg [32:0] sum_r;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin a_r <= 0; b_r <= 0; sum_r <= 0; end
    else begin
      a_r   <= a;           // stage 1: register inputs
      b_r   <= b;
      sum_r <= a_r + b_r;   // stage 2: add registered operands
    end
  end
  assign sum = sum_r;
endmodule
🎤 Meeting angle

PD asks for “a pipeline flop on the CSR read path” — they need shorter combo delay after placement, not a lecture on Verilog.

4

Timing closure (vocabulary)

  • Setup — data must be stable before the capturing edge (with margin).
  • Hold — data must remain stable after the edge.
  • Slack — how much margin you have (negative = fail).
💡 Train schedule analogy

Setup is “arrive before departure.” Hold is “don’t leave the platform too early and take the wrong suitcase.” Slack is how many minutes early you are.

PD + STA prove every path has positive setup and hold slack.

How RTL hierarchy helps PD

  • Placement regions: Synthesis preserves hierarchy; PD can guide blocks near related macros.
  • Incremental closure: Fix timing block-by-block instead of flat 2M-instance chaos.
  • Reuse: Verified I2C IP drops into next chip with known PD footprint.
💼 Interview angle

“Setup vs hold?” — Setup = data too late before clock edge. Hold = data changes too soon after edge. Fix methods differ (pipeline vs buffer delay).

🎯 What to remember

  • PD turns netlists into placed-and-routed geometry.
  • Wire delay and congestion make hierarchy and pipelining matter.
  • RTL choices affect how hard timing closure becomes.
