Lesson 2.6

FPGA vs ASIC — same RTL, different constraints

The same Verilog can target an FPGA or an ASIC. The language is shared; the constraints, IP, clocks, and cost model differ. Good RTL respects both worlds.

Takeaway

Write synthesizable, synchronous, reset-clean RTL. Then apply platform-specific constraints and IP.

2

RTL that ports well

  • Synchronous design with clear clock enables
  • No delays (#) in RTL — TB only
  • Avoid vendor primitives until the boundary wrapper
  • Infer memories with portable templates when possible
  • Document CDC and resets the same way for both
portable_counter.v
// Portable synthesizable counter — FPGA or ASIC friendly
module portable_counter #(
  parameter WIDTH = 8
)(
  input  wire             clk,
  input  wire             rst_n,
  input  wire             en,
  output reg  [WIDTH-1:0] count
);
  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) count <= {WIDTH{1'b0}};
    else if (en) count <= count + {{(WIDTH-1){1'b0}}, 1'b1};
  end
endmodule
Trap

Copy-pasting Xilinx/Intel primitive instantiations into an ASIC flow (or the reverse) locks you in. Keep a thin fpga_clk_wrap / asic_clk_wrap at the top.

3

Soft CPU on FPGA vs custom silicon on ASIC

Same problem — “run firmware” — different platform trade-offs:

🔧

FPGA: soft processor

Drop in MicroBlaze, Nios II, or RISC-V soft core. Recompile bitstream to change RTL around it. Great for prototypes, low volume, fast iteration.

🏭

ASIC: hard / custom core

License ARM/RISC-V hard macro or design your own. Best MHz/mm²/W at millions of units. Months to tape-out; bugs are expensive.

FPGA: CPU is RTL like everything else. ASIC: CPU is often a hardened block next to your logic.

Decision heuristic

<10k units, specs still changing → FPGA (maybe soft CPU). >100k units, cost/power critical → ASIC. Your RTL style stays the same; the wrapper and constraints change.

4

Constraint files — telling tools about clocks & pins

RTL alone does not know board clock frequency or pin locations. Constraint files bridge RTL to physical reality:

  • FPGA (Xilinx): .xdc — pin LOC, create_clock, I/O standards.
  • FPGA (Intel): .sdc — same ideas, Quartus syntax.
  • ASIC: .sdc (Synopsys Design Constraints) — clocks, input/output delays, false paths.
ConstraintFPGA (XDC)ASIC/FPGA (SDC)
Define clockcreate_clock -period 10 [get_ports clk]create_clock -name clk -period 10 [get_ports clk]
Pin locationset_property PACKAGE_PIN W5 [get_ports clk]N/A (ASIC: floorplan)
I/O delayset_input_delay / set_output_delaySame — models board/setup
False pathset_false_path -from [get_ports rst_n]set_false_path -from [get_ports por_n]
constraints_examples.txt
# --- Xilinx Vivado (.xdc) snippets ---
create_clock -period 10.000 -name sys_clk [get_ports clk_50m]
set_property PACKAGE_PIN W5 [get_ports clk_50m]
set_property IOSTANDARD LVCMOS33 [get_ports clk_50m]
set_input_delay -clock sys_clk -max 2.0 [get_ports data_in[*]]
set_output_delay -clock sys_clk -max 2.0 [get_ports data_out[*]]

# --- Synopsys / Intel / ASIC STA (.sdc) snippets ---
create_clock -name clk -period 8.0 [get_ports clk]
set_input_delay  1.5 -clock clk [all_inputs]
set_output_delay 1.5 -clock clk [all_outputs]
set_false_path -from [get_ports rst_n]
set_multicycle_path 2 -setup -from [get_cells div/*] -to [get_cells quot_reg*]

# RTL does not contain these — they ship beside the design per target

Course note: Browser labs skip constraints (no pins, ideal clock). Real FPGA/ASIC flows fail timing reports without them.

platform_wrap_idea.v
// Conceptual — keep platform specifics at the edge
module clk_wrap (
  input  wire clk_pad,
  output wire clk_sys
);
  // `ifdef FPGA
  //   BUFG u_buf (.I(clk_pad), .O(clk_sys));
  // `else
  //   // ASIC: clock buffer / CTS leaf handled by tools
       assign clk_sys = clk_pad;
  // `endif
endmodule

How this course uses both ideas

Labs run in the browser simulator (ASIC/FPGA agnostic). Coding style aims at synthesis-friendly RTL that would map to either. Module 9 adds timing/area thinking that ASIC teams live in — and FPGA timing reports still reward.

Career angle

Job posts saying “FPGA” or “ASIC RTL” both expect: flops, FSMs, lint, CDC awareness, and waveform debug. Platform IP is learnable; bad digital fundamentals are not.
