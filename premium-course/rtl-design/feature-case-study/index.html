RTL Design / Module 1: Complete VLSI Flow
Lesson 1.10

Mini case study: one feature followed Spec → PD

Let’s glue Module 1 together with a single story: adding an I2C master to a small SoC. You will meet this feature again as the course capstone — for now, watch how every stage touches it.

1

Spec

One feature, every stage — Module 11 builds this for real.

  • MUST support standard-mode I2C master writes/reads
  • MUST expose status (BUSY, NACK) to software via CSR
  • SHOULD support clock stretching
  • Acceptance: directed TB proves START → address → data → STOP

2

Architecture

Blocks: CSR bank, byte FSM, bit engine (SCL/SDA timing), APB/AXI-lite slave port, interrupt line.

Clocks: system clock domain for CSR/FSM; note open-drain pad domain considerations.

Draw CDC if any async inputs exist (e.g. external stretch events sampled carefully).

SoC narrative: CPU writes CSR to kick a transfer. Byte FSM sequences address + data bytes. Bit engine toggles SCL and samples SDA at the right micro-delays. IRQ fires on DONE so firmware does not poll forever. PD places I2C near pad ring; STA checks paths from FSM flops to SCL output buffer.

⚠ If architecture skipped

One engineer codes “everything in one module” — reviews take days, unit tests impossible, PD cannot pipeline pad path.

3

RTL design

Implement synthesizable Verilog for bit/byte engines + registers. Keep outputs registered where helpful.

Practice later in Modules 3–7; prove ideas in the simulator.

CSR map sketch + a tiny FSM skeleton (you will expand this in the capstone):

i2c_csr_map.txt
Offset  Name     Bits
0x00    CTRL     [0]=START  [1]=ABORT  [2]=IRQ_EN
0x04    STAT     [0]=BUSY   [1]=NACK   [2]=DONE  (sticky NACK)
0x08    ADDR     [6:0]=7-bit slave address  [7]=R/W
0x0C    TXDATA   [7:0]=byte to write
0x10    RXDATA   [7:0]=byte read from bus
i2c_byte_fsm_skel.v
// Skeleton only — full I2C comes in Module 11
module i2c_byte_fsm (
  input  wire clk,
  input  wire rst_n,
  input  wire start_cmd,
  input  wire bit_done,
  input  wire nack,
  output reg  busy
);
  localparam IDLE = 2'd0, XFER = 2'd1, DONE = 2'd2;
  reg [1:0] state, next;

  always @(posedge clk or negedge rst_n) begin
    if (!rst_n) state <= IDLE;
    else        state <= next;
  end

  always @(*) begin
    next = state;
    busy = 1'b0;
    case (state)
      IDLE: if (start_cmd) next = XFER;
      XFER: begin
        busy = 1'b1;
        if (bit_done && nack) next = DONE;
        else if (bit_done)    next = DONE; // simplify for sketch
      end
      DONE: next = IDLE;
      default: next = IDLE;
    endcase
  end
endmodule

CSR expanded — software contract

i2c_csr_detail.txt
CTRL [0] START   — write 1 to begin (self-clear or pulse)
CTRL [1] ABORT   — force bus recovery
CTRL [2] IRQ_EN  — mask DONE interrupt
STAT [0] BUSY    — read-only, 1 during transfer
STAT [1] NACK    — sticky, W1C (write 1 to clear)
STAT [2] DONE    — sticky, W1C
PRESCALE — divider for SCL from clk_sys
⚠ If RTL skipped proper CSR

Firmware polls wrong bits; “driver bug” debates hide missing sticky NACK spec.

4

Verification

  • Reset clears BUSY
  • Write transaction ACKs
  • NACK path sets sticky status
  • Back-to-back transfers don’t hang

Verification plan bullets

  • Smoke: reset, single byte write, wave review
  • Directed: A1–A5 from spec (ACK, NACK, abort, stretch)
  • Corner: START during BUSY (illegal — must ignore or error)
  • Regression: run on every RTL commit
  • Coverage goal: all FSM states + NACK + DONE IRQ path
tb_i2c_plan.txt
TEST smoke_reset:     rst_n low → BUSY=0, STAT=0
TEST directed_write:  START, addr 0x50, data 0xAB, STOP, expect ACK
TEST nack_addr:       slave NACK on addr → STAT.NACK=1
TEST abort_mid:       ABORT during byte 3 → bus idle, BUSY=0
⚠ If verification skipped

Silicon returns from fab; first board test finds NACK never clears — 8-week debug while competitors ship.

5

DFT / Synthesis / PD / Sign-off (awareness)

  1. DFT — scan-friendly flops; don’t break test modes around pads.
  2. Synthesis — constraints include I2C clocking relationships / IO delays.
  3. PD — place near appropriate IO; watch congestion on bus fabrics.
  4. Sign-off — STA on paths to pads; DRC around ESD/IO cells (team specialty).
💡 Movie production analogy

Spec is the script. Architecture is storyboarding. RTL is filming scenes. Verification is editing. DFT/PD/sign-off are VFX + theatrical release checks. Skipping early stages makes the premiere a disaster.
