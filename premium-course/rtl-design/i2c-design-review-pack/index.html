RTL Design / Module 11: Capstone — I2C Controller
Lesson 11.6 · Review

Design review pack — lint, CDC, timing, area

Shipping RTL means defending it in review. This lesson is your close-out checklist: what to run before you call the I2C capstone done, how to document decisions honestly, and a one-page write-up template you can submit or bring to an interview.

Review mindset

Reviewers don't ask "does it simulate?" — they ask "will it fail in silicon?" Lint, CDC, and timing thinking catch the failures simulation hides. Document what you checked and what you knowingly deferred.

1

Review funnel — before you sign off

Simulation proves functional intent. Lint/CDC/timing prove synthesizability and robustness.

Sim PASS→Lint→CDC notes→Timing→Write-up
2

Lint checklist — I2C-specific

Run your linter (or eyeball with this list) on all synthesizable modules from Lesson 11.4. Fix or document every item.

  • No latches — every always @(posedge clk) assigns all regs in all branches; CSR read in separate always @(*)
  • No multi-drive on oe — only bit engine drives sda_oe/scl_oe; no combinational assign fighting the pad cell
  • No incomplete case — byte FSM default → IDLE; bit engine default → CMD_IDLE
  • Async reset discipline — if using negedge rst_n, document sync deassert plan for ASIC; FPGA often accepts async assert
  • No blocking in sequential logic — = only in testbench and combinational blocks
  • Width mismatches — bit_cnt is 3 bits for 0–7; clkdiv is 16 bits, compared to 16-bit counter
  • Unused inputs — tie off or document reg_rxdata placeholder
  • X propagation — sim shows no X on sda_i after reset (bus model has pull-up)
Top lint failure in student I2C

assign sda = sda_out; without tristate — linter flags multi-driver when slave model also connects. Production fix: IOBUF with T pin tied to !sda_oe.

lint_fix_example.v — pad cell pattern
// Synthesis-friendly pad interface (FPGA IOBUF or ASIC pad macro)
module i2c_pad_io (
  input  wire pad_in,     // from pin
  input  wire core_out,   // 0 = drive low
  input  wire core_oe,    // 1 = actively drive (open-drain: only drive 0)
  output wire pad_out     // to core (sampled input)
);
  // Behavioral model for sim; replace with IOBUF in FPGA flow
  assign pad_out = pad_in;
  // pad pin resolved externally: oe=0 → release (pull-up)
endmodule
3

CDC and open-drain notes

I2C is a slow serial protocol, but pad sampling still crosses clock domains in the strict sense — sda_i changes asynchronously to clk.

SignalDomainRiskMitigation
sda_i (pad input)Async → sys_clkMetastability on ACK sample2-flop synchronizer OR sample only when SCL stable high (our design)
ctrl_startCSR → byte FSMGlitch if pulse too narrowSingle-cycle pulse in same clock domain — OK
irqsys_clk → CPUIf CPU is different clockLevel IRQ + sync in SoC — document as integration task
Open-drain busAnalog/timeRise time, bus capacitancePull-up resistor sizing — board-level, note in review

Interview answer: "SDA is sampled synchronously while SCL is high in the bit engine — we only sample when the protocol guarantees setup time. For production ASIC I'd add a 2-FF sync on sda_i or use a dedicated IO cell with Schmitt input."

CDC honesty

This capstone does not implement a full synchronizer on sda_i — that's a documented gap. Say so in your write-up; reviewers respect honesty over hand-waving.

4

Timing and area intuition

⏱️

Critical path

clkdiv counter decrement → compare to zero → next-state in bit engine. At 100 MHz sys_clk with clkdiv=50, I2C ~1 MHz — plenty of margin.

📐

Area estimate

~200–400 flops: CSR (6 regs), byte FSM (state + shifter), bit engine (counter + phase). Tiny vs a CPU or DSP block.

🔋

Clock gating opportunity

Gate clk to bit engine when byte FSM is IDLE. CSR stays awake for software access. Easy power win in ASIC flows.

The bit engine's cnt register runs every cycle during a transaction — that's intentional (bit-banged timing). Don't try to pipeline it; I2C is inherently sequential.

Timing budget (100 MHz sys_clk, CLKDIV=50): One I2C half-bit = 50 sys_clk cycles = 500 ns Full bit (low+high) = 1000 ns → 1 MHz SCL Full byte (9 bits) ≈ 9 µs + START/STOP overhead

2. Block diagram reference

Three layers: i2c_csr → i2c_byte_fsm → i2c_bit_engine. Software polls STAT.DONE. IRQ optional on completion.

3. Lint results

9

Interview flash cards — defend your capstone

Module 12 goes deeper; use these now to rehearse out loud.

❓

"Walk me through a write."

SW writes ADDR+TXDATA, pulses START. Byte FSM does START, addr byte, ACK check, data byte, ACK, STOP. Bit engine toggles SCL/SDA. STAT.DONE when finished.

❓

"Why open-drain?"

Multiple devices share one wire. Anyone can pull low; no one drives high — pull-up resistor sets idle high. Prevents bus contention.

❓

"What on NACK?"

Slave didn't ACK — STAT.NACK sets. Software decides retry or abort. We still complete STOP in this design to release the bus.

❓

"Biggest risk in silicon?"

Pad sampling without sync; missing clock stretch for slow slaves; insufficient pull-up on long PCB traces. All documented in review gaps.

interview_answers.txt — 30-second pitch
I built a synthesizable I2C master in three layers: CSR for software,
byte FSM for protocol sequencing, and a bit engine that drives open-drain
SCL/SDA with output-enable pads. Verified with a self-checking testbench
covering write-with-ACK, NACK detection, and abort. Documented lint/CDC/timing
in a one-page review. Known gaps: clock stretching, read path, and SDA
synchronizer — I'd add stretch detection first for real silicon.
10

Synthesis and constraints notes

When you move from sim to FPGA/ASIC, add these to your review appendix.

  • Clock constraint: create_clock -period 10 [get_ports clk] for 100 MHz sys_clk
  • False path: sda_i to ACK flop may need set_false_path or multicycle if you add synchronizer
  • IO standard: SCL/SDA pads → LVCMOS33 with open-drain IOBUF on Xilinx; bidir with T pin
  • Reset: If async assert, add set_false_path -from [get_ports rst_n] or sync deassert cell
  • Don't optimize away: Keep pad oe outputs — synthesis must not merge them with internal logic
constraints.sdc excerpt — FPGA example
# I2C master — example timing constraints (adapt to your flow)
create_clock -name sys_clk -period 10.000 [get_ports clk]

# Async reset assert — adjust per your reset strategy
set_false_path -from [get_ports rst_n] -to [all_registers]

# Pad input — if using 2-FF sync, constrain sync chain instead
# set_input_delay -clock sys_clk -max 2.0 [get_ports sda_i]

# Generated I2C is slow — multicycle on bit engine counter path optional
# set_multicycle_path -setup 2 -from [get_cells u_bit/cnt*]
Area vs speed

Don't pipeline the bit engine for "better timing" — you'll break I2C bit timing. If clkdiv path fails, register the compare result one cycle earlier, not add pipeline stages mid-bit.

Register and flop budget — area breakdown

Interviewers sometimes ask "how big is it?" Here's a reasonable flop estimate for your capstone — count them in your RTL if you want exact numbers.

ModuleRegistersNotes
i2c_csr~80 flops6×32-bit shadow regs + control pulses
i2c_byte_fsm~20 flopsstate(4) + shifter(8) + bit_cnt(3) + flags
i2c_bit_engine~25 flopscnt(16) + phase + cmd + scl/sda/oe
i2c_master_top0Wire-only hierarchy
Total~125 flopsTrivial vs 32-bit RISC core (5k–15k flops)

Combinational logic is mostly muxes in CSR read and FSM next-state. Expect <500 LUTs on a small FPGA — dominated by the 16-bit counter compare, not the protocol logic.

Area intuition: Your I2C master ≈ 125 flops ≈ 0.5% of a minimal RV32I core Bit engine cnt ≈ 16 flops ≈ largest single register CSR block ≈ 60% of total area (software interface overhead)
  • Power: Bit engine counter toggles every cycle during BUSY — clock-gate it when idle for ASIC.
  • Floorplan: Pad ring placement for SCL/SDA near IO pins; CSR bus can be far from pads.
  • DFT: Scan-insert FSM states; keep pad oe controllable in test mode for loopback.

How teams actually run RTL review

In industry, your one-page doc becomes a 30-minute meeting. Typical agenda:

  1. Author presents block diagram (5 min) — three layers, CSR map, bus role
  2. Walk one happy-path transaction (5 min) — waveforms or live sim
  3. Reviewer challenges (15 min) — "what on NACK?", "CDC on sda_i?", "stretch?"
  4. Action items (5 min) — fix, waive with rationale, or defer to v2

Your Module 11 write-up is practice for step 3. List gaps before the reviewer finds them — it signals maturity.

  • Bring sim log showing ALL I2C TESTS PASSED
  • Bring lint summary (even if "manual review — 0 issues")
  • Bring waveform PNG of TEST 1 with START/ACK/STOP labeled
  • Bring list of 3 extensions you'd implement next

Sample manager review comments

Real review feedback on student I2C masters — study these before your own review meeting.

Comment 1 — ADDR register

"ADDR stores the shifted byte 0xA0 but your spec says 7-bit unshifted. Fix CSR or update spec — they're out of sync." → Align with 11.2: store 0x50, shift in RTL.

Comment 2 — START sequence

"Waveform shows SCL still high after START — you never pulled SCL low before the first data bit. Illegal per spec." → Bit engine START must end with SCL low.

Comment 3 — CDC honesty

"You sample sda_i combinatorially. Acceptable for FPGA lab clock rates — document as waiver with 2-FF sync planned for v2." → Don't hand-wave; cite review Section 3.

Comment 4 — Verification scope

"Three directed tests are fine for capstone. Add one assertion on START condition before claiming 'protocol verified'." → Optional SVA: sda falls while scl high at transaction start.

Comment 5 — Sign-off

"Approved for FPGA integration. Waive clock stretch and read path for v1 — tracked in roadmap v1.1/v1.2." → This is what a clean sign-off with honest gaps looks like.
