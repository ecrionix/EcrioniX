Lesson 9.6

2-flop, pulse sync & handshake — when to use which

Three synchronizer families cover most CDC boundaries. Pick by signal type: stable level → 2-flop; single-cycle event → pulse sync; multi-bit payload → req/ack handshake (or FIFO for streaming).

Synchronizer

Hardware that safely samples an async signal into a receiving clock domain — trading latency for metastability immunity.

1

2

2-flop synchronizer — stable 1-bit levels

Use when the source signal stays stable for at least two destination clock cycles. The classic pattern for reset flags, mode bits, and slow status lines.

resolve/τ) · never use sync output combo-logically in same cycle
sync_2ff.v
// 2-flop synchronizer — 1-bit level crossing
module sync_2ff (
  input  wire clk_dst,
  input  wire rst_n,
  input  wire async_in,    // from source domain — treat as async
  output wire sync_out
);
  (* ASYNC_REG = "TRUE" *) reg meta, sync;

  assign sync_out = sync;

  always @(posedge clk_dst or negedge rst_n) begin
    if (!rst_n) begin meta <= 1'b0; sync <= 1'b0; end
    else        begin meta <= async_in; sync <= meta; end
  end
endmodule

// Usage: only sample sync_out on posedge clk_dst, never combo-gate it
Trap

2-flop on a pulse shorter than the destination period — the pulse may fall between samples and never be seen. Use pulse sync instead.

3

Pulse synchronizer — single-cycle events

Converts a one-cycle pulse in the source domain into a one-cycle pulse in the destination domain. Common for interrupts and "data ready" strobes.

pulse_sync.v
// Pulse synchronizer — toggle-ack scheme (simplified)
module pulse_sync (
  input  wire clk_src, clk_dst,
  input  wire rst_n,
  input  wire pulse_in,      // 1-cycle in src domain
  output wire pulse_out      // 1-cycle in dst domain
);
  reg toggle_src;
  reg sync_a, sync_b, sync_c;

  // Source: flip toggle on each pulse
  always @(posedge clk_src or negedge rst_n) begin
    if (!rst_n) toggle_src <= 1'b0;
    else if (pulse_in) toggle_src <= ~toggle_src;
  end

  // Dest: 3-flop sync + edge detect
  always @(posedge clk_dst or negedge rst_n) begin
    if (!rst_n) {sync_a, sync_b, sync_c} <= 3'b000;
    else        {sync_a, sync_b, sync_c} <= {toggle_src, sync_a, sync_b};
  end
  assign pulse_out = sync_b ^ sync_c;  // edge → pulse
endmodule
4

Req/ack handshake — multi-bit payload

When you need to move a multi-bit value (not a gray counter), hold data stable and use a handshake: source asserts req, destination acknowledges ack after sampling. Both sides need synchronizers on the control signals.

cdc_handshake_src.v
// Source side — hold data, pulse req, wait for ack_sync
typedef enum logic [1:0] {IDLE, SEND_REQ, WAIT_ACK} src_state_t;
src_state_t state;
reg req;
wire ack_sync;  // ack from dst through 2FF into clk_a

always @(posedge clk_a or negedge rst_n) begin
  if (!rst_n) begin state <= IDLE; req <= 0; end
  else case (state)
    IDLE:      if (payload_valid) begin data_hold <= payload; req <= 1; state <= SEND_REQ; end
    SEND_REQ:  state <= WAIT_ACK;
    WAIT_ACK:  if (ack_sync) begin req <= 0; state <= IDLE; done <= 1; end
  endcase
end
cdc_handshake_dst.v
// Dest side — detect req_sync rising edge, latch data, return ack
wire req_sync;  // req from src through 2FF into clk_b
reg req_prev, ack;

always @(posedge clk_b or negedge rst_n) begin
  if (!rst_n) begin req_prev <= 0; ack <= 0; end
  else begin
    req_prev <= req_sync;
    if (req_sync && !req_prev) begin   // rising edge
      captured_data <= data_bus;        // data stable during req
      ack <= 1;
    end else if (!req_sync && ack)
      ack <= 0;                          // drop ack after src drops req
  end
end
Trap

Never 2FF each bit of a multi-bit bus independently — bits arrive in different cycles. Handshake (or gray/FIFO) keeps the bus coherent.

5

Quick reference checklist

  • Stable 1-bit level → 2-flop sync in destination domain
  • 1-cycle pulse → toggle + edge detect (pulse sync)
  • Multi-bit register write → req/ack handshake
  • Streaming / high throughput → async FIFO (see Async FIFO Overview)
  • Counter crossing → gray code + 2FF (lesson 9.7 preview)
  • Mark sync flops ASYNC_REG; constrain as false paths in SDC
  • Run CDC lint on every block boundary before integration

Latency and throughput trade-offs

StructureTypical latencyMax throughputArea cost
2-flop sync2–3 dst cycles1 toggle per 2×Tdst2 flops
Pulse sync4–6 dst cycles1 pulse per 4×Tdst min3–4 flops + edge logic

Choose the cheapest structure that meets throughput. A status flag polled every millisecond does not need a 512-deep FIFO. A PCIe completion queue does.

🎯 What to remember

  • 2-flop: stable levels. Pulse sync: events. Handshake: multi-bit payloads.
  • Never bit-sync a bus — coherence requires handshake, gray, or FIFO.
  • Control signals cross with 2FF; data stays stable until ack.
  • Match structure to signal type — wrong sync = silent silicon bug.
