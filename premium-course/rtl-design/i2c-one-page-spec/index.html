RTL Design / Module 11: Capstone — I2C Controller
Lesson 11.2

Write the 1-page I2C master/slave spec

Great RTL starts on paper. Before architecture and Verilog, you need a one-page micro-spec that answers: what does this block do, how does software talk to it, what must it guarantee on the bus, and how do we know it works? This lesson walks you through a complete master-focused spec — the same document you'll refine as your capstone deliverable.

Spec discipline

A one-page spec is not vague — it is compressed clarity. Every sentence is either a requirement, an interface definition, or a testable acceptance criterion. If you cannot test it, it does not belong in MUST.

1

Why spec before RTL

Jumping straight into Verilog produces a block that "sort of works" in one testbench but breaks on the second slave, the wrong clock rate, or a missing NACK path. A micro-spec forces you to decide:

  • What transactions the master supports (write, read, write-then-read)
  • How firmware kicks off a transfer and polls completion
  • What happens on NACK, bus error, and timeout
  • What you are explicitly not building (non-goals)
Protocol (11.1)→Spec (11.2)→Architecture (11.3)→RTL + TB

Analogy: The spec is a restaurant menu with prices and allergens. Architecture is the kitchen layout. RTL is cooking. You would not build a kitchen without knowing whether you serve steak or sushi.

2

Block diagram — master IP context

Software sees CSRs. The bus sees open-drain SCL/SDA. Internal FSM + bit engine bridge the two worlds.

3

Complete reference micro-spec

Below is the golden one-pager for this capstone. Copy it into your notebook and annotate decisions you would change for your project.

1. Purpose

i2c_master is a single-master I2C controller that lets firmware initiate write, read, and write-then-read (repeated START) transactions on a shared open-drain bus at Standard-mode (100 kHz) or Fast-mode (400 kHz), selectable via clock divider.

2. Scope — non-goals

  • NOT a slave controller; NOT multi-master arbitration
  • NOT 10-bit addressing; NOT HS-mode (3.4 MHz)
  • NOT DMA — CPU loads TX/RX FIFO registers directly
  • MAY add SMBus alert later; out of scope for v1

3. External interfaces

InterfaceSignalsNotes
CPU (APB)pclk, preset_n, psel, penable, pwrite, paddr[7:0], pwdata[31:0], prdata[31:0], pready32-bit aligned CSRs; always ready in 1 cycle
I2C padsscl_i, scl_o, scl_oen_n, sda_i, sda_o, sda_oen_nOpen-drain: oen_n=0 drives low, oen_n=1 releases
InterruptirqLevel-high while STAT.done or STAT.err set and unmasked

4. CSR map

OffsetNameAccessDescription
0x00CTRLRW[0] EN enable; [1] START auto-clear; [2] RD 1=read 0=write; [3] STOPIE stop-on-NACK
0x04STATRO[0] BUSY; [1] DONE W1C; [2] NACK W1C; [3] ARB_LOST tie 0
0x08ADDRRW[6:0] 7-bit slave address (not shifted)
0x0CTXWONext write byte or register pointer for write-then-read
0x10RXROLast received byte after read completes
0x14DIVRW[15:0] half-period counts in pclk cycles; fSCL ≈ pclk / (4 × DIV)
0x18BCNTRW[7:0] bytes to xfer in read or multi-byte write (1–16)

5. Requirements

MUST Generate legal START, STOP, and repeated START per I2C spec.

MUST Transmit address as (ADDR << 1) | RD with MSB first.

MUST Sample SDA on SCL rising edge; change SDA only when SCL is low (except START/STOP).

MUST Set STAT.NACK if slave does not ACK address or write byte.

MUST Support clock stretching: hold SCL low until scl_i reads high.

SHOULD Abort transaction and release bus if SCL held low > 25 ms (timeout).

SHOULD Insert tBUF bus-free time (≥ 2 SCL periods) after STOP before next START.

MAY Implement 16-byte FIFO in v2; v1 is single-byte TX/RX.

6. Firmware sequence — write 1 byte

  1. Write ADDR, TX, BCNT=1, DIV
  2. Write CTRL = EN | START (RD=0)
  3. Poll STAT.BUSY or wait for irq
  4. Check STAT.NACK; clear DONE
4

Spec writing workshop — bad vs good MUST

Vague requirements cause rework. Compare these pairs — the good version is observable and testable.

❌ Bad MUST:
"The I2C block shall work correctly with all slaves."
✅ Good MUST:
"On address byte NACK, the master SHALL release SDA, generate STOP within 1 byte time, and set STAT.NACK within 2 pclk cycles."
❌ Bad MUST:
"Support fast I2C."
✅ Good MUST:
"With DIV configured for 400 kHz at pclk=50 MHz, measured SCL period SHALL be 2500 ns ±5% in simulation."
❌ Bad MUST:
"Handle errors gracefully."
✅ Good MUST:
"If STOPIE=1 and any byte receives NACK, the master SHALL abort remaining bytes and assert STAT.NACK."
Trap

Mixing implementation ("use a 4-state FSM") into requirements. The spec says what; architecture says how. Exception: pad interface style (open-drain oen) is a requirement because it affects the PCB.

// A1: directed write check (pseudo-code)

8

Firmware cookbook — three recipes

The spec is not complete until firmware engineers can use it without asking you questions. Document these three sequences verbatim.

fw_i2c.c — register-level sequences
#define I2C_BASE  0x40008000
#define CTRL  (I2C_BASE + 0x00)
#define STAT  (I2C_BASE + 0x04)
#define ADDR  (I2C_BASE + 0x08)
#define TX    (I2C_BASE + 0x0C)
#define RX    (I2C_BASE + 0x10)
#define DIV   (I2C_BASE + 0x14)
#define BCNT  (I2C_BASE + 0x18)

// Recipe 1: write 1 byte to slave
void i2c_write_byte(uint8_t slave7, uint8_t data) {
  writel(slave7, ADDR);
  writel(data, TX);
  writel(1, BCNT);
  writel(EN | START, CTRL);       // RD=0 implied
  while (readl(STAT) & BUSY);
  if (readl(STAT) & NACK) handle_nack();
  writel(DONE | NACK, STAT);      // W1C clear
}

// Recipe 2: read N bytes
uint8_t i2c_read_bytes(uint8_t slave7, int n) {
  writel(slave7, ADDR);
  writel(n, BCNT);
  writel(EN | START | RD, CTRL);
  while (readl(STAT) & BUSY);
  return (uint8_t)readl(RX);    // last byte in v1 single-RX
}

// Recipe 3: write-then-read (set reg ptr, read 1 byte)
uint8_t i2c_reg_read(uint8_t slave7, uint16_t reg, int n) {
  writel(slave7, ADDR);
  writel(reg >> 8, TX); writel(reg & 0xFF, TX);  // v2: multi-TX
  writel(EN | START | REP_START_EN, CTRL);       // FSM handles Sr
  // ... poll, read RX
}

9

Timing budget — from pclk to bus

The DIV register is not arbitrary — tie it to a formula in the spec so integrators can configure any supported pclk without your help.

  • MUST Document: DIV = floor(pclk / (4 × f_target))
  • SHOULD Provide a lookup table for common pclks: 25, 50, 100 MHz
  • MAY Auto-compute DIV from a CFG.FMODE bit (100k/400k enum)

Integration note: if pclk can change (DVFS), software must reprogram DIV or pause I2C during clock switch. Document this in the spec assumptions section.

11

Spec review checklist

  • Purpose states master vs slave and supported transaction types
  • Non-goals explicitly exclude at least 3 out-of-scope features
  • CSR map covers CTRL, STAT, ADDR, TX, RX, DIV with bit fields
  • 7-bit address stored unshifted; shift documented in MUST
  • Every MUST is testable — mapped to A1–An acceptance test
  • Open-drain pad interface documented (oen polarity!)
  • Clock stretch and NACK behavior specified (no "hang forever")
  • Firmware sequence written for write, read, and write-then-read
  • Traceability matrix links every MUST to an acceptance test

🎯 What to remember

  • Spec before RTL — compressed clarity, not vague wishes.
  • CSR map + pad interface + irq are the three external contracts.
  • MUST = testable; link each to acceptance test A1–A6.
  • Non-goals prevent scope creep (no multi-master, no 10-bit in v1).
  • Bad specs say "work correctly"; good specs say what happens on NACK in nanoseconds.
