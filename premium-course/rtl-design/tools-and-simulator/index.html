2

Your first 5-minute smoke test

Open the simulator and try this tiny pair (or any starter template already in the tool):

  1. Create a module with one input and one output that ties out = in (wire passthrough).
  2. Write a short testbench that toggles the input a few times.
  3. Press Run.
  4. Open the waveform and confirm out follows in.

Goal: prove you can edit → run → read a wave. That loop is 80% of learning RTL.

If it fails: read the compile log first (typos, missing endmodule, wrong port names). Do not stare at waves until compile is clean.

3

How we will use it in later modules

  • Module 3–5: small combo/seq blocks with self-checking testbenches
  • Module 6–8: FSMs, FIFOs, pipelines — waves become your debugger
  • Module 10–11: directed tests for I2C start/stop/ACK sequences

When a lesson says “open the simulator,” it means this tool — not a separate paid suite.

4

Optional extras (nice, not required)

  • A notes app or paper notebook for design-review bullets
  • GitHub (later) to host your I2C capstone when you are proud of it
  • Any text editor you like for drafting — but always prove it in the simulator
5

Waveform hygiene (learn this early)

  • Always dump clock + reset near the top of the wave list
  • Group related signals (e.g. scl/sda together later)
  • Zoom to the failing time — do not scroll forever
  • Ask: “At this edge, what should change — and did it?”

🎯 What to remember

  • Your default lab is /tools/verilog-simulator/.
  • Master the loop: edit → run → read waves → fix.
  • Compile errors first, functional waves second.
