RTL Design / Module 0: Welcome & How to Learn
Lesson 0.1

Who this course is for (and how to study it)

Welcome. This course is built so a curious beginner can start from zero chip experience and finish able to write, simulate, and defend real RTL — ending with an I2C controller capstone. You do not need a company EDA license to begin.

One-sentence promise

By the end, you will understand the full VLSI map, write clean Verilog, catch common bugs with lint/CDC/timing thinking, verify your work, and ship an I2C design you can show in interviews.

1

This course is for you if…

🌱

Beginner / student

You know basic digital ideas (or are willing to learn Module 2) and want a clear path into RTL jobs.

🔁

Career switcher

You write software or firmware and want to understand how hardware RTL is actually designed and reviewed.

🛠️

Junior RTL / FPGA

You already write some Verilog but want stronger habits: lint, CDC awareness, timing/area thinking, and clean FSMs.

🎯

Interview prep

You want structured practice plus a real protocol project (I2C) instead of random tutorial scraps.

What you need before starting

  • Curiosity + consistency — 45–90 minutes most days beats a 6-hour weekend binge.
  • A browser — all labs run in the free EcrioniX Verilog Simulator. No install required.

You do not need Synopsys/Cadence tools, an FPGA board, or prior SystemVerilog. Verilog-first is enough for this course; SV ideas appear later where they help.

3

How to study (the method that works)

Every lesson in this course follows the same learning loop. Treat it like a recipe — don't skip steps.

Read (story)→ Re-read traps→ Type code→ Simulate→ 3-bullet notes

One lesson ≈ one full loop. Capstone = many loops on the same design.

  1. Read once for the story — ignore code details on the first pass. Ask: "What problem is this solving?"
  2. Re-read the hard box — every lesson has a "trap" or review box. That is the exam. Highlight it in your notes.
  3. Type the code yourself — do not only copy-paste. Muscle memory matters in RTL. If you paste, re-type at least one module from memory.
  4. Run it in the simulator — open waveforms. If you cannot explain a signal at a given clock edge, you do not own it yet.
  5. Write 3 bullets — "What I learned / What still confuses me / What I will try next." Keep these in one running doc.
StepTime (typical)Done when…
First read8–12 minYou can summarize the lesson in one sentence

💡 Study analogy

RTL is like learning a musical instrument. Watching someone play is not practice. Your hands (typing + simulating) are the practice. Scales are boring; they are also why professionals sound effortless.

Common trap: binge-reading five lessons without simulating. You will feel smart for an hour and forget everything by tomorrow. One lesson + sim beats five lessons + scroll.

5

Simulator + notes: use them together

Your two permanent tools are the online simulator and a single notes file (Notion, Google Doc, or paper). Link them:

  • After every sim run — paste the time range where something interesting happened (e.g. "reset release at 100 ns, q went 0→1 at posedge 120").
  • Design-review note — one line per lesson: "A senior would reject this if…" (you will practice this in Lesson 0.3).
  • Question log — unanswered items from your 3 bullets; revisit before the next module cluster.

Template header for your notes doc: Lesson | Date | Learned | Confused | Next | Senior would reject if…

7

Beginner myths (unlearn these early)

❌

"Sim pass = done"

Simulation proves one scenario. Reviewers ask about reset, corners, synthesis, and maintainability.

❌

"Verilog is just C"

Parallel hardware, not sequential software. Time and clocks are first-class.

❌

"I'll learn tools at work"

Companies hire people who already simulate and read waves. This course builds that habit free.

❌

"Skip flow, only code"

Without Module 1 context, you won't know why DFT, timing, or sign-off matter to your RTL style.

8

What "done" means for a lesson

A lesson is complete when you can do all three:

  1. Explain the idea in plain English to a friend.
  2. Run the example (or your variant) in the simulator and read the waveform.
  3. Name one mistake beginners make — and how you would catch it.

Rubric with examples:

CriterionNot doneDone
Explain"It's about flops" (vague)"A flop samples D on posedge clk; async reset forces Q to 0 when rst_n is low"
SimulateCopied code, never ranChanged reset polarity once; saw expected failure; fixed it
TrapCan't name a bug"Blocking assignment in sequential always → sim/synth mismatch"

Honest check: if you skipped the simulator for this lesson, you are not done — even if you read every word. Go back to Lesson 0.2 and run the smoke test.
